# 模型上下文边界

`internal/modelcontext` 是模型调用前后“短句柄 ↔ 持久身份”转换的唯一边界。请求内的临时句柄不能泄漏到工具执行、持久化、UI 或路由层。

## 1. 为什么需要

模型上下文里直接放 UUID、URL、Wiki slug、MCP 服务名会：

- 占用 token；
- 被模型改写/复制错；
- 让不同轮次句柄漂移；
- 把路由字段误当业务参数。

Registry 在请求内分配短句柄，模型只看到 `c1`、`d1`、`w1` 等；执行前还原持久 ID。

## 2. 代码结构

| 文件 | 职责 |
|---|---|
| `registry.go` | `Registry` 门面；请求生命周期只依赖它 |
| `handle_table.go` | 通用双向句柄表 |
| `sources.go` | `cN/dN/bN/wN` 源句柄与工具参数编解码 |
| `citations.go` | 引用协议、`<ref/>` 展开、流式引用 |
| `model_output.go` | 工具结果的精简渲染 |
| `resources.go` | `res://NNNN` 持久资源句柄 |
| `stream.go` | 流式后缀保持/解码 |
| `tool_policy.go` | 每工具字段策略与句柄空间分派 |
| `mcp.go`、`mcp_sources.go` | MCP 路由句柄、定义投影、外部链接候选 |
| `handles.go` | 调用内句柄表 |

## 3. 身份规则

- **持久身份**：UUID、Wiki slug、URL、`resource://...`；可入库/审计。
- **请求句柄**：`cN` chunk、`dN` document、`bN` KB、`wN` web、`msN` MCP service、`mtN` MCP tool、`res://NNNN` resource。
- **工具私有**：`iN` Wiki issue。
- **入库调用**：`cNNN` / `ref-N`。
- 临时句柄在工具执行、持久化、UI 输出前必须解码；不能作为授权/路由依据。

## 4. 请求生命周期

```mermaid
flowchart LR
    A[创建 Registry] --> B[注册源身份]
    B --> C[EncodeMessages]
    C --> D[模型调用]
    D --> E[DecodeToolCalls]
    E --> F[工具执行]
    F --> G[DecodeResponse/StreamDecoder]
```

1. 每个请求/Agent 执行创建一个 Registry。
2. 结构化来源进入上下文时注册身份；Agent 工具用 `EncodeTools` 投影路由枚举和来源摘要。
3. 模型调用前 `EncodeMessages`。
4. 工具调用解析/执行前 `DecodeToolCalls`。
5. 完整响应用 `DecodeResponse`；流式响应每通道一个 `StreamDecoder`。

工具字段里未知的句柄形状会在执行前拒绝。历史 tool call/result 重放使用同一策略，保证句柄不在 Agent 轮次间漂移。

编码顺序由 Registry 管理：资源引用先于源 ID，避免 Wiki slug（如 `summary/<knowledge-id>`）被误编码成 `summary/d1`。

## 5. 引用与可寻址

- `RegisterContextChunk`：为已绑定 KB 的目录项注册导航句柄。
- 历史引用、旧工具历史、工具参数只注册导航句柄。
- `ModelToolResultForTool`/显式检索结果才授权当前执行引用。
- 重读历史来源会提升同一句柄，不重新编号。
- 完整/流式解码都会丢弃没有被当前证据支撑的引用。

## 6. 工具策略

- 知识、图谱、数据、Web、Wiki 工具的 ID 字段通过“工具名 + JSON 字段”白名单集中解码。
- `sourceKeySpaces` 是 ID 字段和句柄空间的唯一事实源；每工具 `sourceIDKeys` 约束可用字段。
- `database_query.sql`/`data_analysis.sql` 有专门策略：只处理引号内可识别句柄，不改 SQL 别名/任意文本。
- Wiki issue ID 使用 `iN` 空间。
- 动态 MCP 工具参数/结果对应用不透明：不能猜测任意 `id/knowledge_id/url` 是持久 ID 并改写；持久资源句柄仍走 `res://NNNN`。
- MCP 路由字段例外：`discover_mcp_tools.server_id` 用 `msN`，`call_mcp_tool.tool_ref` 用 `mtN`；未知路由句柄 fail-closed。

## 7. 可观测性

Langfuse generation observation 记录模型实际收到/返回的编码 payload；Agent tool span 同时记录：

- `model_arguments`：模型发出的句柄；
- `resolved_arguments`：实际执行的持久值；
- `argument_resolution` 和未解析句柄。

敏感工具只记录字段名和解析计数，不记录值。

## 8. 约束

- Langfuse 只观察，不得实现第二套句柄映射。
- 句柄不是授权凭证；解码后仍走资源守卫。
- 新增工具必须声明 `sourceIDKeys`/句柄空间；未知字段 fail-closed。
- 改变编码顺序会破坏引用/路由，必须补回归测试。
