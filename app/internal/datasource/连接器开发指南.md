# 连接器开发指南

本文说明如何为数据源同步框架新增一个外部平台连接器。框架、数据模型与 API 见[数据源同步框架](数据源同步框架.md)。

## 1. 实现范围

一个连接器负责：

- 校验配置（`Validate`）。
- 枚举可选资源（`ListResources`，支持 `parentID` 懒加载）。
- 解析已选资源的祖先路径（`ResolveResourceAncestors`）。
- 全量/增量抓取（`FetchAll` / `FetchIncremental`）。
- 可选：实现流式抓取（`StreamingConnector`），大目录同步不把全部内容放内存。

## 2. Connector 接口

```go
type Connector interface {
    Type() string
    Validate(ctx context.Context, config *types.DataSourceConfig) error
    ListResources(ctx context.Context, config *types.DataSourceConfig, parentID string) ([]types.Resource, error)
    ResolveResourceAncestors(ctx context.Context, config *types.DataSourceConfig, resourceIDs []string) ([]string, error)
    FetchAll(ctx context.Context, config *types.DataSourceConfig, resourceIDs []string) ([]types.FetchedItem, error)
    FetchIncremental(ctx context.Context, config *types.DataSourceConfig, cursor *types.SyncCursor) ([]types.FetchedItem, *types.SyncCursor, error)
}
```

说明：

- `ListResources("")` 返回顶层资源；`parentID` 非空返回直接子级。扁平连接器可忽略。
- `ResolveResourceAncestors` 让懒加载选择器能回显深层已选项；全树/扁平连接器可返回空。
- `FetchIncremental` 返回新游标；游标必须可序列化、可恢复。

### 可选流式接口

大目录建议实现：

```go
type StreamingConnector interface {
    Connector
    FetchStream(ctx context.Context, config *types.DataSourceConfig, cursor *types.SyncCursor, h StreamHandler) (*types.SyncCursor, error)
}
```

`StreamHandler`：

- `Emit(ctx,item)`：逐条入库；返回错误应中止同步。
- `Checkpoint(ctx,cursor)`：按页持久化完整可恢复快照，不是增量补丁。

## 3. 新增步骤

### Step 1：建目录

```text
internal/datasource/connector/<type>/
├── types.go       # 平台模型、资源类型
├── client.go      # 平台 API 客户端
├── connector.go   # Connector 实现
└── *_test.go      # 单测/黄金测试
```

### Step 2：定义类型与配置

- 在 `internal/types/datasource.go` 增加 `ConnectorType<Name>` 常量（如果尚未存在）。
- 配置字段只放连接器需要的平台参数；敏感值由框架 AES 加密。
- 明确资源类型（space/folder/document/wiki 等）和 `FetchedItem` 的外部 ID 规则。

### Step 3：实现 API 客户端

- 封装认证、分页、限流、重试。
- OAuth 刷新逻辑放在 client，不泄漏到 service。
- 错误要可区分：认证失败、权限不足、资源不存在、限流、临时网络错误。

### Step 4：实现 Connector

- `Validate`：调用轻量 API 验证凭据和权限。
- `ListResources`：按层级返回；大目录不要一次拉全树。
- `FetchAll`：给定资源 ID 全量抓取；内容统一转 Markdown/纯文本。
- `FetchIncremental`：用 cursor 的编辑时间/版本/分页 token 跳过未变项。
- 删除检测：同步删除的项要带删除标记，由 service 按 `SyncDeletions` 处理。
- 外部 ID 必须稳定；同一文档重复抓取不能生成重复 Knowledge。

### Step 5：注册

在 `internal/container/container.go` 注册构造函数和 `ConnectorRegistry`：

```go
container.Provide(func() datasource.Connector { return myconnector.NewConnector() })
```

注册顺序不影响；`Type()` 必须唯一且与 metadata 一致。

### Step 6：补 metadata

在 `internal/datasource/connector.go` 的 metadata 表增加：

- `Type`、`Name`、`AuthType`
- 图标、描述、优先级
- 支持的资源类型/能力（增量、删除同步等）

前端“数据源类型”列表直接读该表。

### Step 7：测试

```bash
cd app
go test ./internal/datasource/connector/<type>/...
go test ./internal/application/service/... -run DataSource
```

至少覆盖：

- 配置校验成功/失败。
- 资源枚举（含 `parentID`）。
- 全量抓取字段映射。
- 增量游标推进与恢复。
- 删除标记。
- 分页/限流/认证错误。
- 流式 checkpoint（如实现）。

## 4. 常见模式

### OAuth

- access token 过期前刷新；refresh token 加密存储。
- 刷新失败返回明确认证错误，不静默重试。
- 多租户下 token 不能跨 tenant 复用。

### 分页

- 使用平台稳定游标/next token，不用页码猜测。
- 每页处理完更新 cursor；失败可从最后完整页恢复。
- 限制单次请求大小，避免超时。

### 增量

- 优先使用平台 `updated_at`/version/change log。
- 时间窗口要有重叠，防边界漏项；依赖外部 ID 幂等去重。
- 全量同步可重建基线，但不能把未变更项误删。

### 删除

- 只有确认平台明确返回删除/不存在时才标记删除。
- 权限不足导致的 404 不能当删除。
- 删除同步受 `SyncDeletions` 控制。

## 6. 验收清单

- [ ] `Type()` 唯一，metadata 已注册。
- [ ] `Validate` 能区分认证/权限/网络错误。
- [ ] 资源枚举支持懒加载与祖先回显。
- [ ] 外部 ID 稳定，重复同步幂等。
- [ ] 增量游标可恢复，边界不漏项。
- [ ] 删除同步正确且受开关控制。
- [ ] 大目录内存可控（优先流式）。
- [ ] 单元测试与至少一个真实/黄金样本通过。
- [ ] 凭据不出现在日志、错误信息或同步日志中。
