# 事件系统使用示例

本文给出当前代码里的事件用法：在 Agent/会话链路发送事件，在 SSE handler 订阅并转成前端事件。事件定义见[事件系统](事件系统.md)。

## 1. 初始化

生产由容器注入全局总线；handler 通过 `types.EventBusInterface` 使用：

```go
bus := event.GetGlobalEventBus()
eventBus := bus.AsEventBusInterface()
```

测试使用独立总线，避免污染全局：

```go
bus := event.NewEventBus()
```

## 2. 发送思考/工具/阶段事件

```go
func emitThought(ctx context.Context, bus *event.EventBus, sessionID, requestID, text string) {
    _ = bus.Emit(ctx, event.NewEvent(
        event.EventAgentThought,
        event.AgentThoughtData{Content: text},
    ).WithSessionID(sessionID).WithRequestID(requestID))
}

func emitToolCall(ctx context.Context, bus *event.EventBus, sessionID, name string, args map[string]any) {
    _ = bus.Emit(ctx, event.NewEvent(
        event.EventAgentToolCall,
        event.AgentToolCallData{ToolName: name, Arguments: args},
    ).WithSessionID(sessionID))
}
```

工具结果、阶段、引用、最终答案同理，使用 `AgentToolResultData`、`AgentStageData`、`AgentReferencesData`、`AgentFinalAnswerData`。

## 3. 发送引用与最终答案

```go
bus.Emit(ctx, event.NewEvent(event.EventAgentReferences, event.AgentReferencesData{
    References: refs,
}).WithSessionID(sessionID))

bus.Emit(ctx, event.NewEvent(event.EventAgentFinalAnswer, event.AgentFinalAnswerData{
    Content: answer,
    Done:    true,
}).WithSessionID(sessionID))
```

引用/答案事件顺序会影响前端展示；`final_answer` 之后再发 `agent.complete`，避免流提前结束。

## 4. SSE handler 订阅

```go
type StreamHandler struct {
    bus types.EventBusInterface
    ch  chan<- SSEEvent
}

func (h *StreamHandler) Register() {
    h.bus.On(event.EventAgentThought, func(ctx context.Context, e types.Event) error {
        data, ok := e.Data.(event.AgentThoughtData)
        if !ok { return nil }
        h.ch <- SSEEvent{Type: "thinking", Content: data.Content}
        return nil
    })
    h.bus.On(event.EventAgentReferences, func(ctx context.Context, e types.Event) error {
        data, ok := e.Data.(event.AgentReferencesData)
        if !ok { return nil }
        h.ch <- SSEEvent{Type: "references", Data: data.References}
        return nil
    })
}
```

当前实现参考 `internal/handler/session/agent_stream_handler.go` 和 `qa.go`。

## 5. 中间件

```go
handler := event.ApplyMiddleware(
    func(ctx context.Context, e event.Event) error { return nil },
    event.WithRecovery(),
    event.WithTiming(),
    event.WithLogging(),
)
bus.On(event.EventAgentFinalAnswer, handler)
```

耗时逻辑不要放在同步处理器里；用异步总线或另起任务。

## 6. 测试

```go
func TestToolCallEvent(t *testing.T) {
    bus := event.NewEventBus()
    var got event.Event
    bus.On(event.EventAgentToolCall, func(ctx context.Context, e event.Event) error {
        got = e
        return nil
    })
    bus.Emit(context.Background(), event.NewEvent(event.EventAgentToolCall, event.AgentToolCallData{ToolName: "search"}))
    if got.Type != event.EventAgentToolCall {
        t.Fatalf("unexpected event: %#v", got)
    }
}
```

覆盖：

- 同一事件多个处理器。
- `EmitAndWait` 错误收集。
- 异步模式 panic recovery。
- SSE 事件顺序：thinking → tool_call → tool_result → references → final_answer → complete。

## 7. 接入清单

- 事件类型和数据字段与消费方同步。
- 处理器做类型断言保护，不 panic。
- 生产总线不跨请求复用可变状态。
- 敏感数据不写事件/日志。
- 复杂处理器使用 `WithRecovery/WithTiming`。
- 单元测试 + SSE 顺序测试。
