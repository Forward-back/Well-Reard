# 事件系统

`internal/event` 是进程内事件总线，用于解耦 Agent/会话链路中的思考、工具调用、引用、阶段进度、审批和错误事件。它不是持久化消息队列，重启后不保留事件。

## 1. 组件

| 文件 | 作用 |
|---|---|
| `event.go` | `EventBus`、`Event`、`EventType`、同步/异步分发 |
| `event_data.go` | 各事件的数据结构和 `NewEvent` 辅助函数 |
| `middleware.go` | 日志、计时、panic recovery、链式中间件 |
| `global.go` | 全局单例与便捷函数 |
| `adapter.go` | 适配 `types.EventBusInterface`，避免包循环依赖 |

## 2. 事件总线语义

- `NewEventBus()`：同步模式，处理器按注册顺序串行执行；任一处理器报错立即返回。
- `NewAsyncEventBus()`：每个处理器独立 goroutine，fire-and-forget；panic 被恢复并记录。
- `Emit(ctx,event)`：按模式分发；未提供 ID 时自动生成 UUID。
- `EmitAndWait(ctx,event)`：并发执行所有处理器并等待，收集错误；两种模式都可用。
- `On/Off/Clear`：注册/移除/清空处理器；同一事件类型可注册多个。
- `HasHandlers/GetHandlerCount`：可用于跳过不必要的事件构造。

## 3. 事件类型

| 类别 | 代表事件 |
|---|---|
| 查询 | `query.received`、`query.validated`、`query.preprocess`、`query.rewrite(d)` |
| 检索 | `retrieval.start/vector/keyword/entity/complete` |
| 排序/融合 | `rerank.start/complete`、`merge.start/complete` |
| 生成 | `chat.start/stream/complete` |
| Agent | `agent.query/plan/step/tool/complete` |
| 流式 UI | `thought`、`tool_call`、`tool_result`、`reflection`、`references`、`final_answer`、`rag_stage` |
| 审批/OAuth | `tool_approval_required/resolved`、`mcp_oauth_required/resolved` |
| 会话/记忆/上下文 | `session_title`、`memory_recalled`、`context_compacted`、`user_message_injected` |
| 控制/错误 | `stop`、`error` |

事件类型定义以 `event.go` 为准；新增事件必须同步数据结构和消费方。

## 4. 使用方式

### 订阅

```go
bus := event.GetGlobalEventBus()

bus.On(event.EventAgentToolCall, func(ctx context.Context, e event.Event) error {
    data, ok := e.Data.(event.EventAgentToolCallData)
    if !ok { return nil }
    // 推送到 SSE / 前端
    _ = data
    return nil
})
```

### 发送

```go
bus.Emit(ctx, event.NewEvent(event.EventAgentThought, event.AgentThoughtData{
    Content: "正在分析问题",
}).WithSessionID(sessionID).WithRequestID(requestID))
```

### 中间件

```go
handler := event.ApplyMiddleware(myHandler,
    event.WithRecovery(),
    event.WithTiming(),
    event.WithLogging(),
)
bus.On(event.EventAgentFinalAnswer, handler)
```

## 5. 集成位置

- 会话/Agent handler 订阅事件并转 SSE：`internal/handler/session/agent_stream_handler.go`。
- Agent 运行时发送思考/工具/阶段事件：`internal/agent/*`。
- 会话服务发送引用、最终答案、标题事件：`internal/application/service/session*.go`。
- MCP 工具审批/OAuth 通过事件暂停与恢复执行。

全局总线在 `container.go`/启动阶段初始化；测试使用独立 `NewEventBus()`，不要依赖全局状态。

## 6. 设计约束

- 事件是进程内通知，不保证跨实例投递；多实例部署不能用它做业务消息。
- 同步模式下处理器阻塞主链路；耗时逻辑用异步总线或自己起任务。
- 处理器必须处理 `Data` 类型断言失败，不能假设事件结构永远不变。
- 处理器不能 panic；生产使用 `WithRecovery()`。
- 事件不携带敏感原始凭据；日志中不要打印 token。
