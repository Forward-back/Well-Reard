# 云镜像部署（历史脚本）

> **状态：历史/参考脚本。** 当前主部署入口是仓库根 `deployments/`，本文脚本仍按旧 WeKnora 目录和旧 compose 设计，未随 monorepo 迁移更新。新部署优先使用 `deployments/docker-compose.yml`；只有需要制作云镜像模板时才参考本文。

## 1. 脚本目标

把一台可运行 Docker 的 Linux 实例制作成可分发的云镜像（AMI / 自定义镜像 / Snapshot）：

- 新实例首次开机生成随机密钥；
- 启动默认容器；
- 将初始凭据写入 `/root/weknora-credentials.txt`；
- 自删除一次性 firstboot 脚本；
- 每实例独立密钥，避免镜像泄漏。

适用：腾讯云 Lighthouse/CVM、AWS EC2 AMI、阿里云 ECS、华为云/Vultr、KVM/Proxmox 模板。

## 2. 文件

```text
scripts/cloud-image/
├── 云镜像部署.md
├── prepare.sh                 # 安装 Docker、拉运行时、安装 firstboot
├── cleanup.sh                 # 制作镜像前清理（会锁定 SSH）
├── firstboot.sh               # 新实例首次开机执行
└── systemd/
    ├── weknora.service
    └── weknora-firstboot.service
```

## 3. 与当前部署的差异

本文脚本基于旧版：

- 旧 WeKnora 镜像名（`wechatopenai/weknora-*`）；
- 旧根目录 `docker-compose.yml` / `.env` / `config/config.yaml`；
- 旧五容器栈（frontend/app/docreader/postgres/redis），未包含 `ylsw`；
- 旧源码路径和 `weknora` 命名。

当前仓库：

- compose 在 `deployments/`；
- 栈包含 `frontend/app/docreader/postgres/redis/ylsw`；
- RAG 语料/模型/FAISS 在仓库内 `data/rag/`（gitignore）；
- 服务命名 `Gaze-*`、镜像 `gaze-*`。

直接运行旧脚本会失败或部署旧栈。若必须制作镜像，请先把脚本中的镜像名、compose 路径、服务列表和配置路径改到当前结构，或改用云厂商直接基于 `deployments/` 制作模板。

## 4. 旧流程（仅参考）

```text
1) 准备干净 Linux 实例（systemd + Docker 可装）
2) 拷贝本目录，执行 prepare.sh
3) 访问前端验证功能
4) 执行 cleanup.sh（清私密、锁 SSH、关机）
5) 云控制台制作镜像/快照/AMI
6) 用新镜像创建测试实例，验证 firstboot
7) 分发镜像
```

## 5. 安全注意

- 镜像内不应包含 `.env`、SSH 私钥、真实模型 key、数据库密码。
- `cleanup.sh` 会删除 SSH 授权并锁定登录，执行前确认能通过云控制台恢复。
- firstboot 生成的凭据只在首次启动写一次；分发镜像前确认已清理。
- 当前部署的 RAG 本地数据不应打进镜像；用挂载/初始化脚本提供。

## 6. 当前推荐替代

- 直接分发 `deployments/` + `app/` + `frontend/` + `rag/` 源码，首次启动 `docker compose -f deployments/docker-compose.yml up -d --build`。
- 需要云镜像时，基于当前 compose 制作模板，并在 firstboot 中生成 `deployments/.env` 和外部 RAG 数据目录。
- 具体部署参数见[deployments/README](../../../deployments/README.md)。
