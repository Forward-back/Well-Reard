# 数据入库与元数据

本文描述文档从 app 上传到 RAG 可检索的完整过程：解析、分块、元数据、表格结构化、embedding、FAISS 与 MySQL 写入。架构见[系统架构](系统架构.md)，接口字段见[接口与集成](接口与集成.md)。

## 1. 入库路径

```mermaid
flowchart TB
    A[app 上传文档] --> B[app 解析为 Markdown / 表格]
    B --> C[/ingest 推送]
    C --> D{file_type}
    D -->|md/docx/pdf 文本| E[_ingest_markdown]
    D -->|xlsx / file_bytes| F[_ingest_xlsx]
    E --> G[分块 + 元数据]
    F --> H[表格解析 + schema_registry]
    G --> I[embedding]
    H --> I
    I --> J[(MySQL chunks/documents)]
    I --> K[(FAISS HNSW)]
    J --> L[重载内存 chunk_store/BM25]
    K --> M[可检索]
```

另外保留离线管线：扫描 `RAG_DATA_DIR` 下的语料，适合批量导入和调试；app 栈内默认 `RUN_OFFLINE_INGEST=0`，存量通过 app 上传推送。

## 2. 幂等与删除

- app 推送以 `(document_id, file_name)` 为幂等键；重复推送会删旧重建。
- 文档表有 `UNIQUE uk_source_doc(source_doc_id)`。
- `/delete_document` 按 app `document_id` 删除文档，级联清 chunks、表格、日志、产品提及。
- FAISS HNSW 不支持物理删除；删除后靠 `vector_id` 映射过滤，`rebuild_faiss.py` 做物理重建。
- 清库或更换分块/embedding 后，必须同时删除/重建 `faiss_index.bin`，否则 vector_id 与 DB 错位。

## 3. 解析

`src/ingest/parsers.py`、`pipeline.py` 支持：

| 类型 | 处理 |
|---|---|
| Markdown | 直接使用文本 |
| PDF | PyMuPDF/pdfplumber 提取文本；扫描页可走 OCR |
| DOCX | python-docx 提取段落/表格 |
| XLSX | openpyxl 解析 sheet/行/列，写 `tables_structured` |
| 图片/扫描页 | PaddleOCR / 多模态模型描述，作为文本补充 |

表格的 Markdown 文本仍参与普通分块；xlsx 同时写结构化行表和 schema，供 Text-to-SQL 使用。

## 4. 分块

`src/ingest/chunker.py` 采用 Parent-Child：

| 层级 | 默认大小 | 作用 |
|---|---|---|
| parent | 1200 token | 送入 LLM 的上下文 |
| child | 300 token | 向量/BM25 召回单元 |
| overlap | 128 token | 固定窗口重叠 |

不同文档类型走不同策略：

- Markdown：标题树切分 + 标题链前缀 + 表格/代码块边界。
- 法规 `regulation`：按条款/章节切分，保留上下文邻居。
- 手册 `manual`：按章节切分。
- 新闻 `news`：整篇切分。
- 其他：固定窗口兜底。
- 小于 10 字符的 child chunk 直接丢弃，避免 BGE-M3 拒绝过短文本。

## 5. 元数据

`src/ingest/metadata.py` 优先从文件名解析新格式：

```text
{TYPE}_{DATE}_{ORG}_{PRODUCT}_{TITLE}_{VERSION}_{ZH}.{ext}
```

兼容旧格式正则，抽取：

| 字段 | 说明 |
|---|---|
| `doc_number` | 文号，如银发〔2015〕325 号 |
| `org_name` | 发布机构 |
| `doc_date` | 文档日期 |
| `doc_title` | 清洗后的标题 |
| `doc_type` | regulation/manual/product/report/news/table/general |
| `product_name` | 关联产品；通用表示无特定产品 |

app 推送时还会带企业级字段：

- `lifecycle_status`：draft/effective/expired
- `effective_date` / `expiry_date`
- `superseded_by`
- `sensitivity`：internal/confidential
- `department`
- `custom_metadata`：受控 KV

这些字段反范式到 `chunks`，检索过滤/降权不用 JOIN。

## 6. 表格与 Text-to-SQL

xlsx 入库时：

1. 读取 sheet/行/列。
2. 行数据写 `tables_structured.row_data`。
3. 列信息写 `schema_registry`（类型、示例值、别名）。
4. 生成表格 Markdown 供普通检索。

Text-to-SQL 使用：

- 字段/表名/同义词匹配，优先模板（计数、极值、字段勾稽）。
- 复杂问题才走 LLM 生成 SQL。
- SQL 必须带 `knowledge_base_id` 条件；结果再进入融合/精排。
- SQL 候选没有 chunk 元数据，引用时跳过。
- 计数模板优先于 DISTINCT 模板；多条 SQL 结果合并时用 step id 去重。

## 7. Embedding 与索引

- BGE-M3，取前 768 维；批量 embedding，失败逐条回退。
- 写入 `chunks.vector_id`，FAISS HNSW `M=32`、`ef_search=192`。
- 索引文件 `faiss_index.bin` 在 `RAG_DATA_DIR` 的父目录；容器内挂载 `/app/external`。
- `chunks.status`：pending → embedded / failed；重嵌 daemon 每隔 `REEMBED_INTERVAL_MINUTES` 重试 pending。
- 本地 BGE 与网关 embedding 向量不同源，切换必须重建索引。

## 8. 数据库对象

| 表 | 关键字段 | 说明 |
|---|---|---|
| `documents` | source_doc_id、knowledge_base_id、file_hash、parse_status、doc_summary | 文档主表 |
| `chunks` | document_id、parent_chunk_id、vector_id、chunk_level、status、元数据反范式 | 召回/上下文 |
| `tables_structured` | table_name、row_index、row_data、knowledge_base_id | SQL 行数据 |
| `schema_registry` | table_name、column_name、column_type、sample_values、alias | SQL schema |
| `parse_log` | stage、status、message | 解析日志 |
| `product_mentions` | product_name、chunk_id、document_id | 产品倒排 |

## 9. 入库验证

```sql
SELECT parse_status, COUNT(*) FROM documents GROUP BY parse_status;
SELECT chunk_level, status, COUNT(*) FROM chunks GROUP BY chunk_level, status;
SELECT COUNT(*) FROM tables_structured;
SELECT COUNT(*) FROM schema_registry;
SELECT COUNT(*) FROM product_mentions;
```

期望：

- `documents.parse_status` 全部 success。
- child chunk 全部 embedded，parent 不参与 embedding。
- 表格类文档的 `tables_structured`/`schema_registry` 非空。
- `product_mentions` 非空（有产品文档时）。

## 10. 重新入库

以下情况必须清库重入：

- 修改分块参数/策略。
- 切换 embedding 模型或维度。
- 批量替换同名语料，旧文档残留。
- 索引与 DB vector_id 错位。

步骤见[配置与运维](配置与运维.md)的“清库与重建索引”。

## 11. 当前限制

- 语料不随 git/镜像分发，必须通过 `data/rag/` 挂载。
- 解析质量依赖上游 app/docreader 与 OCR；RAG 不重新解析原始 PDF 的版式。
- HNSW 删除是逻辑过滤，长期运行后需要重建。
- 元数据字段枚举（机构/产品）需要随业务扩展；新增实体要同步 `query_filter`/元数据正则。
- 表格数值题依赖表结构质量；字段定义缺失时 SQL 路无法命中。
