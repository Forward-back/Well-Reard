# 客户端接入

本文给出常见 MCP 客户端的配置模板。所有示例默认使用 stdio；远程 HTTP/SSE 见文末。运行前置、API Key 和传输参数见[安装与运行](安装与运行.md)。

## 1. 通用约定

- `command` 使用 `uv` 的绝对路径最稳；Windows 可用 `where uv` 查询。
- `--directory` 指向本仓库的 `mcp/` 目录，必须是绝对路径。
- `WELLREAD_BASE_URL` 指向 WellRead API 根路径，不是前端页面地址。
- `WELLREAD_API_KEY` 使用租户 API Key；只读问答用 `read` preset。
- stdio 模式下不要让包装脚本向 stdout 写日志，否则会破坏 JSON-RPC 握手。

## 2. Claude Desktop

配置文件位置：

- Windows：`%APPDATA%\Claude\claude_desktop_config.json`
- macOS：`~/Library/Application Support/Claude/claude_desktop_config.json`

```json
{
  "mcpServers": {
    "wellread": {
      "command": "uv",
      "args": [
        "--directory",
        "D:/GitHub项目学习/WellRead/mcp",
        "run",
        "run_server.py"
      ],
      "env": {
        "WELLREAD_BASE_URL": "http://localhost:8080/api/v1",
        "WELLREAD_API_KEY": "<read-preset-token>"
      }
    }
  }
}
```

修改后完全退出并重启 Claude Desktop。若工具列表为空，先在本机执行同一命令确认能启动：

```bash
uv --directory D:/GitHub项目学习/WellRead/mcp run run_server.py
```

## 3. Cursor

在 Cursor 的 MCP 配置（`mcp.json` 或设置页的 MCP Servers）中加入：

```json
{
  "mcpServers": {
    "wellread": {
      "command": "uv",
      "args": [
        "--directory",
        "D:/GitHub项目学习/WellRead/mcp",
        "run",
        "run_server.py"
      ],
      "env": {
        "WELLREAD_BASE_URL": "http://localhost:8080/api/v1",
        "WELLREAD_API_KEY": "<read-preset-token>"
      }
    }
  }
}
```

Cursor 对 stdio 进程的启动超时较敏感。首次启动会解析依赖，必要时先在终端运行一次 `uv sync`。

## 4. KiloCode / 其他 MCP 客户端

支持标准 `mcpServers` 配置的客户端都可使用同一模板：

```json
{
  "mcpServers": {
    "wellread": {
      "command": "uv",
      "args": [
        "--directory",
        "D:/GitHub项目学习/WellRead/mcp",
        "run",
        "run_server.py"
      ],
      "env": {
        "WELLREAD_BASE_URL": "http://localhost:8080/api/v1",
        "WELLREAD_API_KEY": "<read-preset-token>"
      }
    }
  }
}
```

如果客户端只支持 `command` + `args`、不支持 `env`，可在启动脚本或系统环境中设置变量后，把 `args` 简化为：

```json
["--directory", "D:/GitHub项目学习/WellRead/mcp", "run", "run_server.py"]
```

## 5. VS Code / Copilot

VS Code 的 MCP 配置通常写在 `.vscode/mcp.json` 或用户级 `mcp.json`。结构可能随版本变化，核心字段与上面一致：

```json
{
  "servers": {
    "wellread": {
      "type": "stdio",
      "command": "uv",
      "args": [
        "--directory",
        "D:/GitHub项目学习/WellRead/mcp",
        "run",
        "run_server.py"
      ],
      "env": {
        "WELLREAD_BASE_URL": "http://localhost:8080/api/v1",
        "WELLREAD_API_KEY": "<read-preset-token>"
      }
    }
  }
}
```

若当前 VS Code 版本使用 `mcpServers` 键，替换为对应的顶层键即可；不要同时写两套。

## 6. 远程 HTTP / SSE

先启动网络传输服务：

```bash
export MCP_SERVER_AUTH_TOKEN="<strong-random-token>"
uv --directory D:/GitHub项目学习/WellRead/mcp run main.py \
  --transport http --host 0.0.0.0 --port 8000
```

客户端配置成远程 MCP Server，并携带：

```http
Authorization: Bearer <MCP_SERVER_AUTH_TOKEN>
```

Streamable HTTP 地址：`http://<host>:8000/mcp`。SSE 地址：`http://<host>:8000/sse`。

不同客户端对远程 MCP 的 JSON 结构差异较大；如果只支持 `url` 字段，使用上面的 URL 并在自定义 Header 中加 Authorization。HTTP 模式下上传工具默认只能读当前工作目录，需要额外目录时设置 `MCP_ALLOWED_UPLOAD_DIRS`。

## 7. 权限建议

| 客户端类型 | 建议 Key |
|---|---|
| Claude Desktop / Cursor / Copilot 日常问答 | `read` preset |
| 需要把本地文档写入 KB 的自动化 | `write` preset |
| 受信任的运维脚本 | `admin` / full-access，且单独轮换 |

不要把 full-access Key 写进共享的客户端配置或提交到仓库。一个客户端一个 Key，便于撤销和审计。

## 8. 故障排查

- 客户端显示“启动失败”：在终端运行相同 `command`/`args`，看 stderr。
- 工具列表为空：确认 `WELLREAD_API_KEY` 已注入，且 `uv run main.py --check-only` 通过。
- 401/403：Key 失效或权限不足；先换 `read` preset 验证。
- 调用超时：`chat`/`agent_chat` 可调大 `WELLREAD_CHAT_TIMEOUT`。
- Windows 路径问题：JSON 中使用正斜杠或双反斜杠；路径含中文时确认客户端以 UTF-8 启动。
