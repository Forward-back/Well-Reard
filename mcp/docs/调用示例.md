# 调用示例

本文给出典型 MCP 会话流程。工具参数全集见[工具参考](工具参考.md)；不同客户端的调用格式可能不同，这里用“工具名 + JSON 参数”表达语义。

## 1. 发现可用知识库

```text
list_knowledge_bases()
```

返回示例：

```json
{
  "success": true,
  "data": [
    {"id": "e2e3214b-...", "name": "银联商务知识库", "type": "document"}
  ]
}
```

确认 `id` 后，后续调用优先传 UUID，避免名称重名。

## 2. 混合检索

```text
hybrid_search(
  kb_id="e2e3214b-...",
  query="跨境支付合规要求",
  vector_threshold=0.5,
  keyword_threshold=0.3,
  match_count=5
)
```

适合快速检索和调试；不需要创建会话，不产生 LLM 答案。

## 3. RAG 问答

```text
create_session(kb_id="e2e3214b-...", title="合规问答")
```

返回 `data.id` 作为 `session_id`，然后：

```text
chat(
  session_id="<session-id>",
  query="这份知识库主要讲什么？",
  knowledge_base_ids=["e2e3214b-..."]
)
```

返回：

```json
{
  "answer": "...",
  "references": [...],
  "_debug_events": [...],
  "session_id": "<session-id>"
}
```

结束后可删除会话：

```text
delete_session(session_id="<session-id>")
```

`chat` 不传 `knowledge_base_ids` 时只能依赖模型自身知识，通常不是预期行为。

## 4. 写入手工 Markdown

```text
create_knowledge_from_text(
  kb_id="e2e3214b-...",
  title="跨境支付操作手册",
  content="# 操作步骤\n...",
  status="publish"
)
```

`status="draft"` 保存草稿。更新已有手工文档：

```text
update_knowledge_from_text(
  knowledge_id="<knowledge-id>",
  title="跨境支付操作手册（v2）",
  content="# 更新后的内容\n...",
  status="publish"
)
```

## 5. 从文件或 URL 摄入

```text
create_knowledge_from_file(
  kb_id="e2e3214b-...",
  file_path="/data/wellread-uploads/policy.pdf",
  enable_multimodel=True
)
```

文件路径必须存在，并位于 `MCP_ALLOWED_UPLOAD_DIRS` 允许的根目录下；stdio 模式默认不限制根目录，网络模式默认限制在当前工作目录。

```text
create_knowledge_from_url(
  kb_id="e2e3214b-...",
  url="https://example.com/policy",
  enable_multimodel=True
)
```

URL 抓取受后端 SSRF 白名单和解析策略约束。

## 6. Agent 多步问答

```text
list_agents()
get_agent(agent_id="<agent-id>")
create_session(kb_id="e2e3214b-...", title="Agent 会话")
agent_chat(
  session_id="<session-id>",
  query="对比两份制度对跨境支付的要求",
  agent_id="<agent-id>",
  knowledge_base_ids=["e2e3214b-..."]
)
```

Agent 配置为 `kb_selection_mode=none` 或 `selected` 且无内置 KB 时，不传 `knowledge_base_ids` 会失败。先用 `get_agent` 检查。

## 7. Gaze 页面

仅适用于 Gaze-enabled KB：

```text
gaze_index_view(kb_id="<gaze-kb-id>", limit=50)
gaze_search(kb_id="<gaze-kb-id>", query="实体关系", limit=10)
gaze_read_page(kb_id="<gaze-kb-id>", slug="entity/acme-corp")
```

普通 document KB 返回 400；改用 `hybrid_search`/`chat`。

## 8. 批量摄入

批量脚本建议：

1. `list_knowledge_bases` 确认目标 KB UUID。
2. 对每个文件调用 `create_knowledge_from_file`。
3. 失败项记录文件名和异常，不要盲目重试全部。
4. 通过 `list_knowledge` 检查处理状态。

大批量操作使用 `write` preset，且把 Key 的 KB 白名单限定到目标 KB。

## 9. 错误处理

- **400**：参数或 KB 类型不对；检查 `query`、`status`、Gaze KB。
- **403**：Key 权限不足、KB 不在白名单、部门上下文缺失；换 Key 或缩小范围。
- **404**：ID 已删除或不属于当前 Key；重新列取。
- **超时**：`chat`/`agent_chat` 可增大 `WELLREAD_CHAT_TIMEOUT`；不要在超时后立即重复提交长任务。
- **网络错误**：检查 `WELLREAD_BASE_URL` 是否指向后端 API 根路径，而不是前端地址。

## 10. 清理建议

- 临时会话在流程结束后 `delete_session`。
- 测试用 KB/文档使用独立命名，结束后按需删除。
- 自动化脚本不要长期持有 full-access Key；按任务创建短期 Key。
