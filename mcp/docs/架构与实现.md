# 架构与实现

本文说明 MCP Server 的代码结构、请求链路、传输与鉴权实现，以及当前限制。使用方式见[安装与运行](安装与运行.md)，工具清单见[工具参考](工具参考.md)。

## 1. 模块结构

```text
mcp/
├── gaze_mcp_server.py   # GazeClient、31 个 @mcp.tool、三种传输
├── main.py              # 统一 CLI：--transport / --host / --port / --check-only
├── run_server.py        # stdio 启动包装，保留兼容入口
├── run.py               # 最小便捷启动脚本
├── upload_paths.py      # 本地上传路径与传输模式安全校验
├── tests/               # pytest/unittest，32 项
├── scripts/check_imports.py
├── docs/
├── pyproject.toml / setup.py / requirements.txt / uv.lock
└── Dockerfile
```

`gaze_mcp_server.py` 是核心，其他入口只负责参数解析、环境检查和选择传输。

## 2. 请求链路

```text
MCP 客户端
  → stdio / SSE / HTTP 传输
  → @mcp.tool 工具函数
  → GazeClient（requests.Session，X-API-Key）
  → WellRead API /api/v1/*
  → 后端能力、KB 白名单、部门/ACL 守卫
  → JSON 响应或 SSE 答案流
  → MCP 工具返回值
```

MCP 不缓存业务数据，不做二次权限判断；后端返回的 4xx/5xx 通过 `requests.HTTPError` 抛给客户端。

## 3. 传输实现

### stdio

默认模式。`main.py`、`run_server.py`、`gaze_mcp_server.py` 均可启动。stdout 被 MCP SDK 占用为 JSON-RPC 通道，诊断信息必须写 stderr。测试 `tests/test_stdio_stdout.py` 专门守住这一点。

### SSE

`--transport sse` 使用 `mcp.sse_app()`，入口 `/sse`，消息通道 `/sse/messages/`。启动前必须先有 `MCP_SERVER_AUTH_TOKEN`。

### Streamable HTTP

`--transport http` 使用 `mcp.streamable_http_app()`，入口 `/mcp`，当前启用 `stateless_http=True`，客户端初始化不依赖 `mcp-session-id`。测试 `tests/test_mcp_transports.py` 覆盖无状态初始化和 SSE 路径。

网络传输外层包了 `MCPAuthMiddleware`：

- 接受 `Authorization: Bearer <token>` 或 `X-MCP-Auth-Token`。
- 使用 `secrets.compare_digest` 做常量时间比较。
- 未配置 token 时拒绝启动，而不是无鉴权开放。

## 4. 鉴权模型

MCP 有两层凭据，不能混用：

| 凭据 | 方向 | 作用 |
|---|---|---|
| `WELLREAD_API_KEY` | MCP → WellRead | 租户 API Key，放在 `X-API-Key` |
| `MCP_SERVER_AUTH_TOKEN` | 客户端 → MCP | 网络传输共享密钥，放在 Bearer 或 `X-MCP-Auth-Token` |

WellRead API Key 是机器 principal，不是员工身份：

- 不继承公司/部门角色。
- 权限由 `retrieve`、`chat`、`read_agents`、`ingest`、`manage_kbs`、`manage_models` 等 capability 与 KB 白名单决定。
- 部门共享空间依赖部门上下文，公司级 Key 可能 403。
- 审计记录看到的是 Key principal，不是具体员工。

## 5. 并发与连接

`GazeClient` 使用线程本地 `requests.Session`：

- MCP 2.x 会把同步工具放到 worker 线程；`requests.Session` 非线程安全。
- 每个线程懒创建独立 Session，避免 cookie/连接状态串线。
- `chat`/`agent_chat` 是 async 工具，内部通过 `run_in_executor` 调同步 SSE 读取，避免阻塞事件循环。

## 6. SSE 答案流

`chat` 与 `agent_chat` 请求后端 `/knowledge-chat/{session_id}`、`/agent-chat/{session_id}`，解析 `data:` 事件：

- `answer`：累积增量答案。
- `references`：保留引用列表。
- `error`：转成请求异常。
- `complete`：结束流。

最终返回 `{answer, references, _debug_events, session_id}`。读取超时由 `WELLREAD_CHAT_TIMEOUT` 控制。

## 7. 上传路径安全

`upload_paths.py` 只允许上传本地已存在文件：

- 拒绝空路径、空字符、非文件路径。
- 如果设置了 `MCP_ALLOWED_UPLOAD_DIRS`，文件必须位于这些根目录内。
- 未设置时，stdio 不限制根目录；SSE/HTTP 默认限制在进程当前工作目录。
- 路径比较使用 `realpath` + `commonpath`，防止 `..` 和符号链接逃逸。

## 8. 打包与入口

`pyproject.toml` 定义：

- `ylsw-wellread-mcp` → `main:sync_main`
- `wellread-server` → `run_server:main`

运行时模块是顶层模块（`gaze_mcp_server`、`upload_paths` 等），不是 `src/` 包；因此不要在 `mcp/` 根放 `__init__.py`，否则会把目录变成名为 `mcp` 的包，遮蔽真正的 MCP SDK。

## 9. 测试策略

```bash
uv run pytest -q
```

当前 32 项，覆盖：

- `tests/test_mcp_transports.py`：stdio 工具数、SSE 路径、HTTP 无状态、线程本地 Session。
- `tests/test_stdio_stdout.py`：stdio 启动不得污染 stdout。
- `tests/test_file_path_security.py`：上传路径越界与传输模式。
- `tests/test_create_knowledge_from_text.py`、`tests/test_update_knowledge_from_text.py`：手工文档写接口。
- `tests/test_agent_id_resolution.py`、`tests/test_kb_id_resolution.py`：名称/UUID 解析。
- `tests/test_module.py`：入口、依赖、文件结构。

`scripts/check_imports.py` 是手工 SDK 结构检查，不属于 pytest 套件。

## 10. 当前限制

- 部门共享空间没有 API Key 部门语义；`list_shared_knowledge_bases` 可能 403。
- Gaze 工具只对 Gaze-enabled KB 有效，普通 KB 返回 400。
- `create_tenant`/`list_tenants` 是多租户遗留接口，单租户部署不建议开放。
- 工具错误直接透传后端状态，没有统一的 MCP 错误码映射；客户端需要处理 `HTTPError`。
- `chat` 不向 MCP 客户端流式输出增量，只返回聚合后的答案和引用。
- 删除类工具无二次确认，安全边界依赖 API Key 权限和客户端策略。

## 11. 扩展点

- 新增工具：在 `GazeClient` 增加 API 方法，用 `@mcp.tool()` 注册顶层函数，docstring 写清参数与权限。
- 新增传输：在 `run_*` 中复用 `MCPAuthMiddleware`，网络传输必须继续强制 `MCP_SERVER_AUTH_TOKEN`。
- 部门感知 Key：需要后端支持 API Key 的部门上下文；仅改 MCP 无法解决共享空间 403。
- 工具级权限：可在 MCP 层增加 allowlist/denylist，但最终授权仍应在后端。
