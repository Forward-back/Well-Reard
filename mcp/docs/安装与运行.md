# 安装与运行

本文说明 MCP Server 的运行前置条件、API Key、环境变量、三种传输方式和常见故障。客户端配置模板见[客户端接入](客户端接入.md)，工具参数见[工具参考](工具参考.md)。

## 1. 前置条件

- Python 3.10 及以上。
- 推荐使用 `uv`；也支持 `pip` 与 `python -m venv`。
- WellRead 后端可访问，默认地址 `http://localhost:8080/api/v1`。
- 一个租户 API Key。MCP 不接收员工账号密码，也不复用前端 JWT。

## 2. 获取 API Key

由 company_admin 在租户 API Key 管理界面创建，或调用：

```http
POST /api/v1/tenants/{tenant_id}/api-keys
Authorization: Bearer <company_admin JWT>
Content-Type: application/json

{
  "name": "mcp-read",
  "preset": "read"
}
```

创建响应里的 `data.token` 只返回一次，作为 `WELLREAD_API_KEY` 使用。

| preset | 展开能力 | 适用场景 |
|---|---|---|
| `read` | `retrieve`、`chat`、`read_agents`、`message_history` | 只读检索、问答、列 Agent |
| `write` | `read` + `ingest` | 额外允许上传/更新文档 |
| `admin` | full access | 可信自动化；包含删除、建库、模型管理等 |

`manage_kbs`、`manage_models` 不在 preset 中。需要建库或模型管理时，显式创建带对应 capability 的 Key，或使用 `admin`。

## 3. 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `WELLREAD_BASE_URL` | `http://localhost:8080/api/v1` | WellRead API 根地址 |
| `WELLREAD_API_KEY` | 空 | 租户 API Key；未设置时多数工具会 401/403 |
| `WELLREAD_CHAT_TIMEOUT` | `300` | `chat`/`agent_chat` SSE 读取超时（秒） |
| `WELLREAD_VERIFY_SSL` | `true` | 自签证书开发环境可设 `false`，不建议生产使用 |
| `MCP_TRANSPORT` | `stdio` | `stdio`、`sse`、`http` |
| `MCP_HOST` | `127.0.0.1` | 网络传输监听地址 |
| `MCP_PORT` | `8000` | 网络传输监听端口 |
| `MCP_SERVER_AUTH_TOKEN` | 空 | SSE/HTTP 必填；客户端用 Bearer 或 `X-MCP-Auth-Token` |
| `MCP_ALLOWED_UPLOAD_DIRS` | 网络传输默认当前工作目录 | 文件上传工具的允许根目录，逗号分隔 |

`GAZE_BASE_URL`、`GAZE_API_KEY`、`GAZE_CHAT_TIMEOUT`、`GAZE_VERIFY_SSL` 仍作为兼容别名读取；同时设置时 `WELLREAD_*` 优先。

## 4. 安装与 stdio 启动

```bash
cd mcp
uv sync --extra test
export WELLREAD_BASE_URL="http://localhost:8080/api/v1"
export WELLREAD_API_KEY="<token>"
uv run run_server.py
```

等价入口：

```bash
uv run main.py
uv run python -m gaze_mcp_server
uv run python run.py
```

`run_server.py` 和 `main.py` 默认使用 stdio。stdio 模式下 stdout 是 JSON-RPC 通道，诊断信息只写 stderr；不要在启动脚本里向 stdout 打印日志。

## 5. HTTP / SSE 传输

网络传输必须设置共享密钥：

```bash
export MCP_SERVER_AUTH_TOKEN="<strong-random-token>"
uv run main.py --transport http --host 127.0.0.1 --port 8000
```

- Streamable HTTP：`POST http://127.0.0.1:8000/mcp`，无状态会话。
- SSE：`uv run main.py --transport sse --host 127.0.0.1 --port 8000`，入口 `/sse`，消息通道 `/sse/messages/`。
- 客户端请求头：`Authorization: Bearer <MCP_SERVER_AUTH_TOKEN>` 或 `X-MCP-Auth-Token`。

网络模式下上传工具默认只允许读取进程当前工作目录；需要读取其他目录时显式设置：

```bash
export MCP_ALLOWED_UPLOAD_DIRS="/data/wellread-uploads,/srv/docs"
```

## 6. Docker

镜像默认以 HTTP 传输启动：

```bash
docker build -t ylsw-wellread-mcp .
docker run --rm -p 8000:8000 \
  -e WELLREAD_BASE_URL="http://host.docker.internal:8080/api/v1" \
  -e WELLREAD_API_KEY="<token>" \
  -e MCP_SERVER_AUTH_TOKEN="<token>" \
  ylsw-wellread-mcp \
  ylsw-wellread-mcp --transport http --host 0.0.0.0 --port 8000
```

需要本地上传文件时，挂载目录并设置 `MCP_ALLOWED_UPLOAD_DIRS`。容器内不要挂载整个仓库或宿主机根目录。

## 7. 运行检查

```bash
uv run main.py --check-only
uv run python scripts/check_imports.py
uv run pytest -q
uv build
```

- `--check-only` 检查依赖和环境变量，不启动服务器。
- `check_imports.py` 检查 `mcp` SDK 结构与导入。
- `pytest` 当前覆盖客户端、上传路径安全、stdio/HTTP 传输、入口和 ID 解析。
- `uv build` 验证 wheel/sdist 打包；构建产物 `dist/` 可删除。

## 8. 常见问题

### `list_shared_knowledge_bases` 返回 403

API Key 是公司级机器身份，没有部门上下文；部门共享空间接口可能直接拒绝。使用 `list_knowledge_bases` 查本 Key 可访问的 KB，或在后端为 MCP 场景设计部门感知的 Key。

### `gaze_*` 返回 400

Gaze 工具只适用于启用了 Gaze 页面的知识库。普通 document KB 请使用 `hybrid_search`、`list_knowledge` 或 `chat`。

### `create_tenant` / `list_tenants` 意义不大

WellRead 是单租户本地部署；这两个工具来自多租户 API。除非明确做租户管理，否则不要给 MCP 客户端开放。

### 上传文件被拒绝

检查文件是否存在、是否在 `MCP_ALLOWED_UPLOAD_DIRS` 下、路径是否包含空字符。stdio 模式默认不限制根目录；SSE/HTTP 默认限制在当前工作目录。

### 中文输出乱码

Windows 终端可能是 GBK。设置 `PYTHONUTF8=1` 或 `chcp 65001` 后再启动；MCP 协议本身使用 UTF-8。

### 端口被占用

`MCP_PORT` 或 `--port` 改端口；HTTP 测试常用固定端口，冲突时先检查残留进程。

## 9. 安全边界

- MCP 的定位是“用 API Key 访问 WellRead”，不是员工身份代理；审计记录看到的是 Key principal。
- full-access Key 绕过员工角色与部门权限，泄露影响大。普通 AI 客户端只发 `read` Key。
- 不要把 HTTP/SSE 端点直接暴露到公网；必须暴露时使用反向代理、TLS 和强随机 `MCP_SERVER_AUTH_TOKEN`。
- 删除 KB、删除文档、删除分块、创建模型等工具不要开放给不可信客户端。
