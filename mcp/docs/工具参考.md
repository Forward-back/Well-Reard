# 工具参考

本文是 MCP Server 的完整工具目录，共 31 个工具。工具名即 MCP 客户端看到的名称；参数使用 Python 类型标注生成 JSON Schema。

## 1. 通用约定

- **KB 标识**：大多数 `kb_id` 参数同时接受 UUID 和知识库名称。名称解析失败或重名时优先使用 UUID。
- **分页**：`page` 从 1 开始，`page_size` 默认 20；返回结构由后端决定，通常包含 `data` 与 `total`。
- **返回**：除 `chat`/`agent_chat` 外，工具返回后端 JSON 响应；`chat` 返回 `{answer, references, _debug_events, session_id}`。
- **错误**：后端 4xx/5xx 会以 `requests.HTTPError` 抛出；参数错误通常是 400，权限不足是 403，资源不存在是 404。
- **权限**：工具本身不做二次授权，最终由 WellRead 的 API Key capability、KB 白名单和资源守卫决定。MCP 不提供员工角色语义。
- **破坏性工具**：`delete_*`、`create_model`、`create_tenant` 会改变后端状态；不要向不可信客户端开放 full-access Key。

## 2. 空间管理

| 工具 | 签名 | 用途 | 说明 |
|---|---|---|---|
| `create_tenant` | `(name, description, business, retriever_engines=None)` | 创建空间 | 多租户 API；单租户部署通常不需要 |
| `list_tenants` | `()` | 列出空间 | 同上；返回受后端权限限制 |

## 3. 知识库

| 工具 | 签名 | 用途 | 说明 |
|---|---|---|---|
| `create_knowledge_base` | `(name, description, embedding_model_id='', summary_model_id='')` | 新建 KB | 需要 `manage_kbs` 或 full-access |
| `list_knowledge_bases` | `()` | 列出当前 Key 可访问的 KB | 只返回自有/授权范围，不含部门共享空间 |
| `list_shared_knowledge_bases` | `()` | 列出部门共享入 KB | 依赖部门上下文；公司级 API Key 可能 403 |
| `get_knowledge_base` | `(kb_id)` | KB 详情 | KB 可传 UUID 或名称 |
| `delete_knowledge_base` | `(kb_id)` | 删除 KB | 破坏性；需要管理权限 |
| `hybrid_search` | `(kb_id, query, vector_threshold=0.5, keyword_threshold=0.3, match_count=5)` | 向量 + 关键词混合检索 | 只读；适合调试和轻量 RAG |

## 6. 会话与问答

| 工具 | 签名 | 用途 | 说明 |
|---|---|---|---|
| `create_session` | `(kb_id, max_rounds=5, enable_rewrite=True, fallback_response='Sorry, I cannot answer this question.', summary_model_id='', title='', description='')` | 创建绑定 KB 的会话 | `chat` 前必须先建会话 |
| `get_session` | `(session_id)` | 会话详情 | 只读 |
| `list_sessions` | `(page=1, page_size=20)` | 列出会话 | 只返回当前 Key 可见范围 |
| `delete_session` | `(session_id)` | 删除会话 | 破坏性 |
| `chat` | `(session_id, query, knowledge_base_ids=None, web_search_enabled=False)` | RAG 问答 | 建议始终传 `knowledge_base_ids`；返回答案与引用 |
| `agent_chat` | `(session_id, query, agent_id, knowledge_base_ids=None, web_search_enabled=False)` | Agent 多步问答 | `agent_id` 必填；Agent 无内置 KB 时必须传 KB |
| `list_agents` | `(page=1, page_size=50)` | 列出 Agent | 只读 |
| `get_agent` | `(agent_id)` | Agent 详情 | 查看 `kb_selection_mode` 与内置 KB |

`chat` 需要先创建会话，且 `session_id` 与 `knowledge_base_ids` 必须属于当前 Key 可访问范围。`agent_chat` 的 Agent 配置决定工具集与默认 KB；如果 Agent 的 `kb_selection_mode` 为 `none` 或 `selected` 且列表为空，必须显式传 KB。

|---|---|---|---|

## 9. 权限与 Key 选择

| 使用面 | 推荐 Key | 说明 |
|---|---|---|
| 只读检索、`chat`、列 Agent | `read` | `retrieve` + `chat` + `read_agents` + `message_history` |
| 上传/更新文档 | `write` | 在 read 基础上增加 `ingest` |
| KB 生命周期、模型、租户 | `admin` 或显式 capability | `manage_kbs`、`manage_models` 等；风险最高 |

注意：

- `list_shared_knowledge_bases` 依赖部门上下文，API Key 是公司级 principal，可能 403；需要部门共享能力时应在后端扩展 Key 的部门语义。
- `create_tenant`/`list_tenants` 是遗留多租户接口，单租户内部署通常不应暴露。
- Gaze 工具不是通用检索；普通 KB 用 `hybrid_search` 或 `chat`。
- 破坏性工具没有二次确认；风险由客户端和 Key 权限控制。

## 10. 错误排查

| 现象 | 常见原因 | 处理 |
|---|---|---|
| 400 `query_text is required` | 检索参数为空 | 传非空 `query` |
| 400 Gaze 相关 | KB 不是 Gaze-enabled | 改用普通 KB 工具 |
| 403 | Key 缺少 capability、KB 不在白名单、无部门上下文 | 换 preset/Key 或缩小 KB 范围 |
| 404 | KB/文档/会话 ID 不存在或已删除 | 先 `list_*` 确认 ID |
| 超时 | `chat` LLM/检索慢 | 调大 `WELLREAD_CHAT_TIMEOUT` |
| 401 | API Key 无效 | 重新创建 Key，确认 `WELLREAD_API_KEY` |
