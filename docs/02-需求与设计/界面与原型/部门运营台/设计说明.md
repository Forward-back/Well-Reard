# 部门运营台设计说明

> 状态：优化中
> 最后更新：2026-10-26
> 目标读者：前端、产品、设计
> 关联：[治理台与审计](../../功能与交互/治理台与审计.md)、[部门管理工作台](../../功能与交互/部门管理工作台.md)

## 1. 设计目标

部门运营台不是“库存清单”，而是部门知识工作的“经营周报”。它回答三个问题：

1. **团队干得怎么样？** 贡献与协作周转。
2. **知识够不够用？** 知识缺口与内容新鲜度。
3. **知识有没有被用起来？** 检索趋势与共享影响力。

原型：`运营台原型.html`。

## 2. 信息架构

| 区块 | 业务价值 | 数据来源 |
|---|---|---|
| 知识缺口 Top5 | 员工问了但库没答上的主题，指导内容选题 | 检索审计 hits=0/低分聚合 |
| 热门检索 Top5 | 验证 KB 价值与维护优先级 | 检索审计聚合 |
| 团队贡献榜 | 识别贡献者与沉默者 | 审计日志（上传/合并/评论）聚合 |
| 协作周转 | CR 平均滞留、issue 平均响应 | CR/issue 时间戳差值 |
| 共享影响力 | 共享出 KB 被外部门检索次数 | 检索审计 join 部门 |
| 部门 KB 健康 | 文档数、解析失败、超龄内容、生命周期分布 | KB/文档聚合 |
| 一句话摘要 | 10 秒掌握本周 | 上述聚合的模板化生成 |

页面结构：顶部部门待办条 → KPI 卡 → 主次两栏（趋势/缺口/贡献 + 审计摘要/健康）。异常置顶，正常流水折叠。

## 3. 关键交互

- 指标卡点击进入对应明细；知识缺口可“指派撰写”，创建草稿文档 + CR + 站内通知。
- 时间窗口固定为近 7 日，与公司治理台同源同口径；切换窗口需全局一致。
- 零值 ≠ 无数据：无历史记录时显示引导态（“部门还没有检索记录，邀请同事来试试”），不渲染 0 占位。
- 不展示员工原始问题；缺口与热门主题只以聚合主题/哈希呈现。
- 每个面板标注刷新频率或统计窗口。

## 4. 边界

- 只读视图；成员、审计员、技能等写操作在[部门管理工作台](../../功能与交互/部门管理工作台.md)。
- manager 可进入部门审计；knowledge_admin 只看板，不看审计。
- 部门指标与公司治理台同名指标必须同源同口径，避免数字对不上。

## 5. 当前差距

- 知识缺口/热门检索/贡献榜依赖检索审计与审计聚合，当前检索审计只存 query hash，Top5 尚未落地。
- 缺口指派闭环未实现。
- 趋势图、模板摘要、共享影响力面板仍在原型阶段。
- 部门看板当前已有近 7 日检索、无命中、共享出检索、CR 周转、open issue 基础聚合。
