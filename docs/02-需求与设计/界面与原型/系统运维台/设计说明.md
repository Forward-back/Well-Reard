# 系统运维台设计说明

> 状态：优化中
> 最后更新：2026-10-26
> 目标读者：前端、产品、设计、运维
> 关联：[系统运维台](../../功能与交互/系统运维台.md)、[系统总览](../../../01-项目总览/系统总览.md)

## 1. 设计目标

运维台不是“全绿状态陈列”，而是可排障的驾驶舱：出问题时第一屏能告诉运维“哪里坏了、影响什么、下一步做什么”；正常时也能看到积压、容量和配置风险。

原型：`运维台原型.html`。

## 2. 信息架构

七个一级分区：总览、模型与引擎、集成、运行队列、安全与审计、账号运维、系统设置。

总览页：

1. 顶部运维待办条：按 P1/P2/P3 汇总活跃告警；无告警时显示“全部正常”。
2. 五张健康卡：应用、解析、存储、模型、队列；附依赖与最近检查时间。
3. 队列分格：待处理/执行中/重试/归档 + 最近 2 分钟负载趋势。
4. 资源水位：存储、待处理队列、归档任务，带阈值红线。
5. 模型通道：按供应商聚合已配置模型；支持跳转测试连通性。
6. 右侧：当前告警 + 最近平台审计（操作人、可读动作、对象、时间）。
7. 底部动作快捷入口：刷新状态、处理队列、测试模型、查看安全审计。

## 3. 关键交互

- 环境徽章：DEV/PROD 使用醒目颜色，避免误操作。
- 每个面板标注刷新频率（实时/10s/30s/5min），明确数据新鲜度。
- 队列用分格数字而不是环形占比图；归档是历史累计，不能与实时状态混在一个环里。
- 存储与队列显示阈值线；数据不足时不编造“预计耗尽时间”。
- 审计人话化：动作、对象名称、操作人、结果；不显示裸 UUID。
- 快捷入口是动作型，不是左侧导航的复读。
- 无数据时切换为空态或通道连通性视图，不显示“暂无数据”占位。

## 4. 边界

- 只服务 system_admin；不进入 KB 正文、问答、精读、共享空间、公司治理。
- 集成作用域等场景只读 KB/Agent 名称、ID、计数，不读正文与会话。
- 账号运维只做身份创建、重置密码、授予/撤销系统管理员；不改公司角色、部门归属。
- 高风险动作二次确认并写系统审计。
- 详细规则见[系统运维台](../../功能与交互/系统运维台.md)。

## 5. 当前差距

- 告警由健康状态实时派生，没有独立告警表与通知渠道。
- 队列趋势仅前端最近 2 分钟滚动窗口；无 24h 趋势与通道延迟。
- 备份、证书、演练等超期事项尚未进入运维待办。
- 模型并发空态、审计筛选/分页/导出仍需打磨。
- 精读模型配置入口仍需从公司管理员侧迁移到运维台。
