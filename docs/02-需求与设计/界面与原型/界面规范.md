## 1. 图标设计规范(设计源 → 双色 SVG)

### 1.1 素材来源

`frontend/design/ui-source/icons/` 下的 PNG(50×50)为图标素材,共 20+ 个(加载/标签/搜索/分类/对话/协作/治理等)。PNG 均为黑白线条+抗锯齿,视觉上呈现深、浅两种灰色调。

### 1.2 矢量化方法(关键: 禁止手绘复刻)

**手绘 SVG 复刻会出现畸变(用户确认过一次返工),必须走像素级矢量化:**

1. 解码 PNG,按 alpha 分两层: `dark = alpha > 150`,`light = 20 < alpha <= 150`(两层互斥,light 层含抗锯齿灰边,还原后与原图观感一致)
   - 例外(2026-10-21): 灰底填充+黑线图标(如手绘机器人)的整块浅灰身体与黑线 alpha 均为 255,继续按 alpha 分层会把身体并入 dark 层、覆盖眼睛。此类图标须按亮度分层: `alpha > 20` 为前提,`dark = luma < 128`,`light = luma >= 128`。
2. 对每层做 marching squares 轮廓提取(50×50 网格,边界中点插值),相邻线段链成闭合环
3. 输出 SVG `<path fill-rule="evenodd">` 填充路径(每层一条 path,多环以子路径拼接;孔洞靠 evenodd 正确镂空)

### 1.3 双色规范

| 层 | 填充色 | 聚焦/激活时 |
|------|--------|------------|
| dark(主体线条) | `#575e66` | `var(--td-success-color)` 品牌绿 |
| light(浅灰线条+抗锯齿边) | `#b3bac2` | `var(--td-success-color)` + `opacity: 0.55`(保持双色层次) |

### 1.4 交互细节(已对齐)

- **图标变色**: 聚焦/展开时图标变绿(深→品牌绿,浅→55% 透明绿),失焦/收起恢复;**不做**选中后常绿
- **触发实现**: 弹层类控件绑弹层可见状态(如 `statusFilterPanelVisible`/`tagFilterPanelVisible`);图标为内联 SVG(16×16),CSS 控制 fill 切换,不用 PNG img + filter hack
- **hover 边框统一(2026-10-19 用户确认)**: 筛选栏所有控件(搜索框/全部标签/全部类型/全部状态/来源/时间范围)悬浮时边框一律变品牌绿 `var(--td-brand-color)`。实现: `.doc-filter-bar` 内 `:deep(.t-input:hover)`、`:deep(.t-select:hover .t-input)`、`:deep(.t-date-range-picker:hover .t-input)` + 两个自定义触发器 `&:hover { border-color: var(--td-brand-color) }`(原为透明/灰边框,已改)。后续新增筛选控件必须沿用此交互

### 1.5 已应用位置

| 位置 | 素材 | 触发 |
|------|------|------|
| 入库工具栏「解析状态」触发器 prefixIcon | `icons/loading.png` | 弹层可见(`statusFilterPanelVisible`) |
| 入库工具栏「全部标签」触发器 prefixIcon | `icons/tag.png` | 弹层可见(`tagFilterPanelVisible`) |

## 2. 入库 UI（已实施）

### 2.1 状态聚合(纯前端,后端 7 态不动)

| UI 状态 | 后端 parse_status |
|---------|------------------|
| 处理中 | pending / processing / finalizing / **draft**(手动内容草稿归此桶) |
| 已完成 | completed |
| 失败 | failed |
| 已取消 | cancelled |
| (不显示) | deleting(后端列表默认排除) |

处理中桶内细分态(pending 等待中/processing 处理中/finalizing 整理优化中/draft 草稿)在卡片 tooltip 展示。

### 2.2 状态下拉(用户修正过两轮: chips 行 → t-select 下拉 → 触发按钮+复选面板)

**最终形态(仿「全部标签」交互,用户确认)**:
- 触发按钮(`doc-status-filter-trigger`,样式同 tag 触发器: 灰底 32px 圆角) + `t-popup` 复选面板(处理中/已完成/失败/已取消 四行 t-checkbox,点选即时生效)
- **选中项不堆进框内**: 按钮 label 显示「全部状态」(空)或选中项顿号连接(如「处理中、失败」)
- **label 文字恒为黑色**(`--td-text-color-primary`),未点击/无选中时也是黑色——与其他筛选栏文字配色一致;悬浮/展开时底变白+边框显现
- 后缀 chevron 展开时转品牌蓝并 180° 旋转;图标交互见 §1.4
- 后端配套: `parse_status` 参数支持**逗号分隔多值**(IN 查询),白名单 7 态(含 draft,拒绝 deleting),非法值 400;改动在 handler/knowledge.go + types.KnowledgeListFilter.ParseStatuses + repository/knowledge.go

### 2.3 视图切换(已对齐: 二档 + 内层切换)

- 工具栏 [列表|看板] 二档按钮;列表模式下保留原 grid/list 小切换(分隔线隔开)
- localStorage 键 `gaze.kb.docs.viewMode` 存 grid/list/board;列表内层偏好会话内记忆(切回列表恢复上次小视图)
- 默认: 列表 + 全部状态

### 2.4 看板模式

- 看板模式:**每个选中状态一栏**(面板选中几态显几栏,全不选 = 4 栏: 处理中/已完成/失败/已取消)
- **保持分页**(用户选择,非全量): 每栏独立分页 `page_size=20`,栏内滚动到底自动加载下一页(复用无限滚动模式)
- **每栏上下滚动独立**(用户确认): 看板模式下外层 `doc-scroll-container` 加 `is-board` 置 `overflow: hidden`,滚动只发生在各栏 body 内
- **已修 bug(2026-10-19)**: 看板宽度取决于「列表模式数据是否为空」——列表数据为空时容器命中 `.is-empty { display: flex }` 把看板压成内容宽(如单选已取消时栏宽 222px 不撑满;选中含已完成时列表拉到 120 篇、容器不空、看板正常)。修复: `is-empty` 条件排除看板模式(`viewMode !== 'board' && ...`)。headless CDP 实测: 修复后单栏 973px 撑满
- 精简行卡: 图标+标题+更新时间,处理中行 hover tooltip 显细分态;点击打开文档
- 无拖拽、无多选/批量操作
- 数据加载: `boardState`(reactive,按桶分栏状态)+ `listKnowledgeFiles` 直调,每栏请求带该桶展开的 parse_status 多值
- 组件: `frontend/src/views/knowledge/components/DocumentBoardView.vue`(纯展示,数据由 KnowledgeBase.vue 拉取)

### 2.5 验证方式

- 前端改动经本地 vite dev server(`npm run dev` → http://localhost:5173,HMR 即时生效,`/api` 代理到 app 6152),验证完统一 `docker compose build frontend`
- 后端经 air 热重载容器自动重编译;若未见生效 `docker restart Gaze-app` 兜底(docker logs 流序不可靠,以进程/接口实测为准)

## 3. 对话页（已实施）

### 3.1 消息身份头部

- **用户消息**: 移除气泡背景与内边距,字号 16px、行高 1.625,与回答一致;右上显示用户名 + 24px 方形圆角头像(radius 6px,无头像时显示用户名首字母品牌绿底)。头像在消息右侧「悬挂」:消息区 `padding-right: 30px`(头像 24 + 间距 6),头部 `margin-right: -30px`,保证用户名末字与消息末字右对齐、头像位于最右。用户消息上方不再显示 @知识库 tag;文件/标签等其他 mention 保留。
- **回答消息**: 左上显示手绘机器人 SVG +「Gaze」。`bot_msg` 左 padding 28px,头部 `margin-left: -28px`;图标占 22px + 6px 间距,G 与回答首字左对齐。机器人用亮度分层矢量化(见 §1.2 例外),dark 层(眼睛/轮廓)品牌绿实心、light 层(身体)品牌绿 55% 透明。
- **验证几何**: 用户名右缘 = 消息右缘;Gaze 左缘 = 回答首字左缘(2026-10-21 headless 实测)。

### 3.2 指代改写卡片

- 无边框折叠态:「已改写 · 原指代 → 目标实体」,画笔图标常绿;展开态「改写已完成」+ 原句橙色下划线、改写实体绿色高亮、映射行(锚定来源 + 跳到出处)、must_keep/耗时/实体槽 chips、编辑改写/使用原文检索。
- LLM 返回 `source_text`/`target`/`anchor_text`,后端逐字校验后才展示;校验失败只显示基础文本,不画错误高亮。
- 跳到出处: 优先 `anchor_text` 在上一轮回答中的位置,前端对旧 meta 用 target 分段候选回退;滚动到高亮实体本身,闪绿 1.2s。
- 映射/来源/耗时持久化在 `messages.query_rewrite_meta`(迁移 000104/000016),刷新后保留。

### 3.3 知识库看板与筛选(2026-10-21 修复)

- 看板数据必须按 `{ data, total }` 顶层读取;刷新后直接进入看板时依赖 watch `immediate:true`;看板无文件夹行,请求带 `folder_recursive:true`,否则子目录文档不显示。
- 状态筛选弹层被 Teleport 到 body,scoped 样式不匹配,需用 `overlay-class-name` + 非 scoped 全局样式;四个复选项竖排。
- 文档类型/来源选项按产品口径精简: 类型 PDF/DOCX/XLSX/TXT/MD/URL/手动创建;来源 本地上传/URL 导入/手动创建/API。

## 4. 登录页

### 4.1 布局

- 左侧展示区约 58%，右侧登录卡约 42%；窄屏上下堆叠。
- 左上角是文字 Logo `WellRead`，字体 `WellReadSerif`；桌面 `40px`，≤768px 与 ≤480px 为 `24px`。
- 不显示右上角“官方网站 / GitHub”入口，也不恢复旧轮播卡片。

## 6. ISSUE(已关闭)

### IS-1 状态下拉在用户浏览器「依旧不行」(2026-10-19 已解决 ✅)

- **教训**: 重启 vite dev 后必须确认端口归属;大改后建议强刷;可 headless CDP 验证(Node 24 原生 WebSocket 驱动 Edge,KB 路由=/platform/knowledge-bases/:kbId)

## 7. 约定速查

- 图标一律双色(深 `#575e66` / 浅 `#b3bac2`),聚焦/展开变绿(深→品牌绿,浅→绿 55% 透明),失焦恢复
- 筛选栏所有控件 hover 边框一律变品牌绿,交互必须一致
- 筛选触发器 label 文字恒黑色(primary),选中项顿号连接显示,不在框内堆标签
- UI 状态 4 桶: 处理中(含 draft)/已完成/失败/已取消;deleting 永不显示
- 看板 = 选中状态即栏,栏内独立分页滚动加载,外层容器不滚动
- 用户消息无气泡背景;用户名/头像右上、Gaze/机器人左上,按 §3.1 的悬挂对齐实现
- 文档类型/来源只保留 §3.3 精简后的选项,新增筛选项须先对齐
- ui-source PNG 只做素材源,前端用其矢量化 SVG,不用原 PNG
