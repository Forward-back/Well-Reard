# 公司治理台设计说明

> 状态：优化中
> 最后更新：2026-10-26
> 目标读者：前端、产品、设计
> 关联：[治理台与审计](../../功能与交互/治理台与审计.md)、[部门管理工作台](../../功能与交互/部门管理工作台.md)

## 1. 设计目标

公司治理台让 company_admin 在不读取业务正文的前提下，判断公司知识资产、部门健康、共享关系和风险。治理页只负责“看与查”，成员、部门等写操作放在“管理”页，两个入口边界固定。

原型：`治理台原型.html`。

## 2. 信息架构

治理页顶部两个页签：运营看板、审计日志。

运营看板：

1. 治理待办条：待审 CR、未处理 issue、审计异常、公开 KB 待复核。
2. 资产 KPI：知识库（共享出/入）、文档、摄取健康、成员、近 7 日会话、审计异常。
3. 部门健康对比：KB、文档、成员、月活跃、内容新鲜度、近 7 日检索、健康度；行可下钻。
4. 共享关系动态：谁把哪个 KB 共享给哪个部门；新部门是否自动获得全量共享。
5. 内容动态：解析失败、废止、deny 等异常置顶，正常解析折叠。
6. 检索质量：命中率、无答案率、点踩等聚合；不展示原始问题。

审计日志：

- 异常聚合条：连续 denied、短时间批量操作等。
- 筛选：时间、动作、结果、操作人、对象。
- 表格：时间、可读动作、操作人、对象、结果、详情。
- 分页与导出；导出本身写审计。

## 3. 关键交互

- 部门行点击下钻到部门聚合，不进入文档正文。
- 共享关系、内容异常可跳转到对应聚合或 KB 元数据，不打开正文。
- 审计动作人话化，对象补全名称与所属部门；不显示裸 UUID。
- 治理待办点击进入协作/审计等只读明细；写操作跳转管理页。
- 零值 ≠ 无数据：无历史记录显示引导态；真实零值显示 0 并标注统计窗口。
- 每个面板标注刷新频率或统计窗口。

## 4. 边界

- company_admin 只进入治理、管理；问答、精读、KB、共享空间、历史会话全部 403。
- 治理只消费聚合统计与审计元数据，不读取正文、会话内容、员工原始问题。
- 技能目录全部部门只读；创建/编辑/启停/删除/授权归部门 manager/knowledge_admin。
- 管理页只做成员、部门动作；治理/审计不在管理页重复。

## 5. 当前差距

- 部门健康对比、共享关系动态、检索质量面板仍在原型阶段。
- 审计异常自动聚合、动作人话化、对象补全、分页/导出仍需打磨。
- 知识缺口/热门检索未落地；检索审计只存 query hash。
- CR 审阅历史未进入治理审计。
- 审计保留期与导出范围尚未形成固定策略。
