# 废弃子系统切割

> 状态：历史
> 日期：2026-10-25
> 关联：[当前进度](../当前进度.md)、[系统运维台](../../02-需求与设计/功能与交互/系统运维台.md)

> 目标：删除产品已停用的 HTTP 管理面与独立子系统，保留聊天链路仍实际依赖的运行时。
> 原则：先删路由/handler/DI，再删无外部引用的独立包；被聊天/检索链路使用的运行时包不硬删，避免破坏问答。

## 1. 切割结论

| 子系统 | 处理 | 删除内容 | 保留原因 |
|---|---|---|---|
| FAQ | 删除 HTTP 面 | `handler/faq.go`、`RegisterFAQRoutes`、DI、Router 字段、相关 API Key 测试 | FAQ 仍作为 KB 类型参与导入/检索/智能体上下文，服务层保留 |
| Favorites | 后端全链删除 | repository/service/handler/types/interfaces 5 文件、路由函数、DI；前端星标/收藏入口已删 | — |
| Evaluation | 全链删除 | evaluation handler/service/types/interfaces、dataset service/types、metric 包与 metric_hook、DI、路由、API Key 能力 | 无外部引用；检索指标代码仅评测使用 |
| Organization | 管理面删除 | `handler/organization.go`、`service/organization.go`、组织路由、DI、Service 接口 | `OrganizationRepository` 与类型仍被 KB/Agent 分享的底层查询使用 |
| Web Search | 删除管理 HTTP 面 | 3 个 handler、DTO、路由、DI、`manage_web_search` 能力 | Agent 运行时联网搜索仍保留 |
| Memory | 删除 HTTP 面 | `handler/memory.go`、`routes_memory.go`、DI | 会话长期记忆/召回仍被聊天链路使用 |
| IM | 全链删除 | `internal/im` 整包（含 wecom/feishu/dingtalk 适配器，62 文件）、回调/管理路由、handler、DI、启动注册 | 产品停用且无运行时调用方 |
| MCP | 删除管理 HTTP 面 | MCP service/credentials/oauth/metadata/usage handler、DTO、路由、DI、`manage_mcp_services` 能力 | Agent 运行时 MCP 管理器保留；外部 MCP Server 保留并适配 |
| Sandbox | 删除管理 HTTP 面 | sandbox config/skill handler、env-var handler、管理路由、DI | Agent 工具与会话终端仍依赖 sandbox |
| Agent | 删除作者面 | `handler/custom_agent.go`、作者/分享路由、RBAC creator lookup、DI、`manage_agents` 能力 | 内置智能体与聊天链路仍依赖 agent service/engine；只读 `GET /agents` 与 `agent-chat` 为外部接入恢复 |

## 2. API Key 能力收口

删除以下已无路由承载的能力，前后端同步：

- `run_evaluations`
- `manage_spaces`
- `manage_web_search`
- `manage_mcp_services`
- `manage_agents`

保留 `read_agents`：外部客服/Agent/MCP 客户端需要解析智能体；对应只读 `GET /agents`、`GET /agents/:id` 已重新注册，不恢复作者面。

保留：`retrieve`、`chat`、`ingest`、`manage_kbs`、`message_history`、`manage_models`、`manage_data_sources`、`manage_vector_stores`、`manage_storage_backends`、`manage_channels`、`manage_members`、`manage_tenant_settings`、系统级能力。
历史 API Key 中已删除的能力在读取时会按未知能力丢弃，不影响鉴权。

## 3. 部署能力声明

`deploymentCapabilitiesFromRouter` 改为明确声明：

- `organizations=false`
- `agents=false`
- `im=false`
- `mcp=false`
- `web_search=false`
- `sandbox=false`

前端设置页据 `/system/capabilities` 隐藏对应入口。

## 5. 保留与后续

- **运行时不可直接删**：`internal/agent`、`internal/sandbox`、`internal/mcp`、`internal/infrastructure/web_search`、`internal/application/service/memory` 仍被聊天/精读/检索链路引用。要彻底移除，需先下线会话中的 agent 运行时，另立需求。
- **前端残留**：FAQ 管理、收藏/星标、MCP 设置、记忆设置已删除；Sandbox 面板/终端与聊天内 MCP 工具展示仍在，因为 `agent-chat` 运行时保留。
- **Swagger**：`app/docs/swagger.*` 已于 2026-10-25 重新生成，已删端点不再出现。
- **数据库**：`user_resource_favorites`、评测相关表与迁移未删，避免破坏已有库；可在确认无数据后单独写 drop migration。

## 6. 外部接入回补（2026-10-25）

产品定位需要让外部客服、网页问答和 Agent 接入，因此回补最小运行面，不恢复管理面：

- **Agent 只读**：`GET /agents`、`GET /agents/:id`，`handler.AgentRuntimeHandler`；新增/编辑/删除/复制仍关闭。
- **Agent 对话**：`POST /agent-chat/:session_id` 重新注册，使用 `chat` 能力；外部 API Key 可创建会话并对话。
- **API Key 能力**：恢复 `read_agents`，并加入 read/write 预设；`manage_agents` 仍关闭。
- **Memory**：只恢复聊天时间线的 `DELETE /memory/items/:id`（forget），记忆管理台仍关闭。
- **MCP 服务**：`app/YLSW-WellRead-mcp` 保留；App 内 MCP 服务管理页/路由仍关闭，二者不是同一层。
- **MCP 适配**：
  - 共享 KB 改用当前接口 `GET /shared-space/knowledge-bases`，保留旧嵌套响应兼容解析。
  - 环境变量改为 `WELLREAD_BASE_URL` / `WELLREAD_API_KEY` / `WELLREAD_CHAT_TIMEOUT` / `WELLREAD_VERIFY_SSL`，旧 `GAZE_*` 继续兼容且新前缀优先。
- **前端清理**：删除收藏/星标 UI、FAQ 管理 UI（保留历史 FAQ 检索命中提示）、MCP 设置页、记忆设置页；`ListSpaceSidebar` 死组件删除。
- **前端接口适配**：共享 KB 改走 `/shared-space/knowledge-bases`；移除 `/organizations`、`/im-channels` 请求；新增只读 `/web-search-providers` 运行时列表，聊天输入区可正确判断联网搜索可用性。
- **Swagger**：已重新生成，`evaluation`、`user/favorites`、`mcp-services`、`sandbox-configs`、`im-channels`、`faq/entries` 等端点不再出现。
