## 1. 登录与入口

**登录后看不到知识库/问答，只有治理和管理？**  
这是 company_admin 的正常形态。公司管理员不进入业务页面；如需阅读文档，请使用部门角色账号。直接访问业务 URL 会返回 403。

**system_admin 登录后没有问答入口？**  
正常。系统管理员默认进入 `/ops`，只做技术运维；业务路由 403。双身份账号可从头像菜单切换到公司工作台，公司侧按 membership 角色显示。

**菜单项为什么和文档截图不一致？**  
菜单由能力码派生，随角色和版本变化。以当前账号实际能力为准；权限口径见[角色生态位规定](../02-需求与设计/角色与权限/角色生态位规定.md)。

## 2. 知识库与文档

**上传后一直“处理中”或失败？**  
查看解析状态与失败原因；失败可重解析。扫描件需要 OCR/VLM，解析未完成的文档不能作为问答/精读依据。

**为什么看不到某个 KB？**  
可能不属于当前部门、未被共享、被 ACL deny，或 KB 在共享空间只读入口。跨部门共享不会让接收方获得编辑/删除/ACL 权限。

**共享入 KB 为什么不能编辑？**  
共享入是只读入口；可阅读、检索、问答、提交 issue/评论，但不能上传、编辑、删除、共享、ACL。

**删除 KB/文档为什么失败？**  
KB 删除仅 manager；文档删除是 manager/knowledge_admin。editor/viewer 没有删除权。部门可能还有共享、协作或引用，需要先处理影响。

## 3. 问答与引用

**回答没有引用，能作为正式结论吗？**  
不能。没有引用的判断只能作为线索；正式结论必须能回溯到文档/章节/原文。

**为什么拒答？**  
没有可靠证据、问题与业务无关、权限范围内无文档，都会拒答。系统不会用模型记忆冒充公司事实。

**引用跳转不到原文？**  
可能文档已更新、版本已回滚或权限变化。引用会标注来源与版本；失效时以当前可读版本为准。

**多个版本的数字对不上？**  
先核对文号、生效时间和生命周期；多版本问题不能混用。数值计算需要列算式并自查。

**员工原始问题会出现在治理看板吗？**  
不会。检索审计只保留 query hash 与聚合，治理台不展示原始问题。

## 4. 协作与版本

**审批通过了，为什么还没生效？**  
审批通过不等于合并。合并前还需至少一名其他审阅者/部门审计员批准，且只有 manager 可以合并；合并后才生成新版本。

**谁能审批 CR？**  
manager 可审批/驳回他人提交的 CR；部门审计员可审批/驳回本部门所有 CR；单 CR reviewer 只对该 CR 生效。提交人不能审批自己的 CR，manager 也不例外。审批者不能合并，除非同时是 manager。

**“审计员”能看审计日志吗？**  
不能。这里的审计员是 CR 审批授权，不是审计日志查看权。审计日志归 manager（部门）和 company_admin（公司）。

**CR 冲突/锚点丢失怎么办？**  
系统会提示冲突或锚点丢失，需要重新对齐内容后重提；不会静默覆盖。

**回滚会删除历史吗？**  
不会。回滚生成新版本，历史保留；旧 chunk 引用的迁移/失效仍是待优化项。

## 5. 精读与技能

**精读和普通问答有什么区别？**  
精读读取用户选定的整篇文档，按计划逐步阅读、提问、记笔记，产出报告；普通问答是检索片段后回答。

**精读可以选择部门技能吗？**  
不能。精读固定使用内置 `grill-with-docs` 策略；部门技能只用于普通问答。

**精读为什么只能用 5 篇、单个 KB？**  
控制上下文、权限复核和成本；后续是否放宽需产品决策。

**技能选择器没有选项？**  
本部门没有已启用技能，或技能被停用。让 manager/knowledge_admin 在技能管理中创建并启用。

**技能会执行脚本或扩大 KB 权限吗？**  
不会。技能是提示词级过程知识，不执行脚本，不改变检索范围、ACL、引用。

## 6. 治理与运维

**部门看板和公司看板数字对不上？**  
同名指标应同源同口径；若不一致，记录统计窗口与范围后反馈。当前部分面板仍在升级。

**为什么运维台某些卡片是空的？**  
没有数据时显示空态，不显示假趋势。检查刷新频率、依赖连接与时间窗口。

**模型/解析/存储在哪里配置？**  
system_admin 在 `/ops` 运维台配置全局资源；knowledge_admin 只能在 KB 内选择已启用的实例，不能新增凭据。

**忘记密码/账号被锁怎么办？**  
system_admin 在“账号运维”中重置密码或创建身份；公司成员/部门归属由 company_admin 管理。

## 7. 部署与数据

**RAG 问答不可用，但 app 正常？**  
检查 ylsw 容器、模型网关、FAISS 索引与本地数据目录 `data/rag/`；RAG 不可用时问答不做静默降级。

**迁移仓库后问答全空？**  
RAG 数据在仓库内 `data/rag/`（gitignore），需要复制该目录并在 compose 中挂载；仅复制代码不够。

**能不能把真实文档放进演示环境？**  
不建议。演示环境使用样例数据；真实文档涉及密级、授权与审计，应在生产态按权限导入。

**发现文档与代码不一致怎么办？**  
以当前代码/运行结果为准，记录到对应功能文档的“当前实现与差距”，不要按旧文档直接改代码。
