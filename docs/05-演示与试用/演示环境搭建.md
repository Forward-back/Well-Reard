# 演示环境搭建

> 状态：规划
> 最后更新：2026-10-26
> 目标读者：售前、实施、运维
> 关联：[演示指南](演示指南.md)、[部署手册](../../deployments/README.md)、[当前进度](../03-进度与交接/当前进度.md)

## 1. 目标

为演示/试用提供一套与生产隔离的环境：样例文档、固定演示账号、可重复重置，不接触真实公司数据与密钥。

当前演示沿用开发栈手工准备；独立“演示环境 + 种子数据 + 一键重置”仍在规划中。

## 2. 规划形态

| 项 | 方案 |
|---|---|
| 部署 | 单机 Docker Compose，复用 `deployments/docker-compose.yml` |
| 数据 | 独立 tenant、独立 PostgreSQL/Redis 卷、独立 RAG MySQL/FAISS |
| 语料 | 演示文档集，放仓库内 `data/rag/`，不进入 git/镜像 |
| 账号 | 六角色演示账号 + 双身份账号，密码只在演示环境使用 |
| 配置 | 独立 `.env`，模型凭据使用演示 Key，禁止复用生产 Key |
| 重置 | 规划脚本：清空演示卷、重建种子数据、重放样例文档 |

## 3. 搭建步骤（规划）

1. 准备一台内网单机，安装 Docker 与 Compose；内存建议至少 16 GB。
2. 复制仓库并准备仓库内 `data/rag/`：`Data/`、`models/`、`faiss_index.bin`（该目录 gitignore，不随 git 分发）。
3. 复制 `deployments/.env.example` 为 `deployments/.env`，填写演示数据库口令、模型网关地址与演示 Key。
4. 启动六服务：frontend、app、docreader、ylsw、postgres、redis。
5. 等待 `/health` 200；检查 RAG 本地目录挂载与索引写入权限。
6. 导入演示文档并等待解析完成；确认至少一组共享出/共享入。
7. 创建六角色账号与默认部门；配置 1 个已启用技能、1 个精读模型。
8. 执行演示脚本准备 issue/CR/版本数据；跑一遍[演示指南](演示指南.md)主线。

## 4. 隔离与安全

- 演示环境必须与生产网络、数据库、模型 Key 隔离。
- 不使用真实客户文档、员工信息、真实问题日志。
- 演示账号密码公开在演示材料中，禁止用于生产；生产账号必须单独创建。
- 演示环境可对外开放时，限制入口、加访问控制，并定期重置。
- 演示数据可丢弃；但重置前确认没有需要保留的演示反馈。

## 5. 重置与维护

- 重置前停止六服务，备份需要保留的演示反馈。
- 清空演示 PostgreSQL/Redis 卷与 RAG 索引，重新导入种子数据。
- 重置后重新核对账号 caps、共享关系、示例 CR 状态。
- 每次演示前按[演示指南](演示指南.md) §2 检查，避免空看板、失败解析和不可用模型。
