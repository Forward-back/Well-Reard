# 管理仪表盘与设置委派需求

> 状态：Phase 5 基础闭环已实施（部门/公司治理台、审计查询、scope/403、部门运营聚合、Settings KV 能力）；趋势图、导出与视觉打磨待做。
> 依赖：`能力_角色_页面路由需求.md` 的 caps/路由/403/设置矩阵；`共享空间权限需求与设计` 的部门/KB/ACL 数据范围。
> 关联：`能力_角色_页面路由需求.md`。

## 1. 背景

当前系统页面以知识库操作为主，缺少面向管理层与部门负责人的聚合视图。后续新增管理层仪表盘、部门运营台、审计查询页时，必须同时解决：

- 页面能不能看：路由 caps。
- 能看多少数据：后端按能力注入数据 scope。
- 设置谁可改：设置委派，而不是所有设置只给 company_admin。

本需求只覆盖管理与设置委派面，不重做 KB/文档/ACL 主链路。

## 2. 页面与能力

| 页面 | 路由 | required_caps | 数据范围 |
|---|---|---|---|
| 部门运营台 | `/platform/governance?tab=dashboard`（部门 scope） | `stats:dept_read` | 仅本部门 |
| 公司治理台 | `/platform/governance?tab=dashboard`（公司 scope） | `stats:company_read` | 全公司，可按部门下钻 |
| 审计查询 | `/platform/governance?tab=audit` | `audit:dept_read` 或 `audit:company_read` | 部门 / 公司 |
| 系统管理 | `/ops/security`、`/ops/settings` 等运维分区 | `settings:system_manage` | system_admin |

- 页面组件可复用，路由与数据 scope 分离；不存在“管理页面”独立类别。
- 未授权菜单不渲染；手输 URL 进统一 `/403`。
- company_admin 只看聚合治理数据与审计事件元数据，不进入 KB 正文；治理页不提供正文读取与导出。
- manager/knowledge_admin 只能看本部门统计；不得通过前端传 `department_id` 拉其他部门数据。
- knowledge_admin 有 `stats:dept_read`，没有 `audit:dept_read`。

## 3. 仪表盘数据范围

### 3.1 部门运营台

面向 manager / knowledge_admin（knowledge_admin 只读统计）。部门运营台首版包含：经营 KPI、治理待办、模板化摘要、本部门 KB 健康、协作周转、审计异常摘要；检索面板只做聚合，不展示原始问题。

- 本部门 KB 数量、文档数、处理中/失败数
- 最近上传/最近更新
- 共享入/共享出 KB 数
- 成员数、部门角色分布
- 检索/问答使用量（若已有统计）

后端规则：

- scope 固定为调用者 department_id。
- 前端传 department_id：必须等于调用者部门，否则 403。
- 不返回其他部门聚合数据。

### 3.2 公司治理台

面向 company_admin：

- 全公司 KB/文档/成员/部门总量
- 各部门分布与下钻
- 共享范围概览
- 审计/风险摘要
- 只读，不提供业务写操作

后端规则：

- scope = 全公司。
- 可按 department_id 下钻，但仅聚合数据。
- 治理台只返回聚合与审计事件元数据，不读取 KB 正文，也不提供导出。
- 不因仪表盘权限获得 KB 阅读、编辑、共享、ACL、建库能力。

### 3.3 审计查询

- company_admin：全租户审计。
- manager：本部门审计（操作人/部门/KB 范围）。
- knowledge_admin：无审计能力。
- 审计结果按能力注入 scope；前端传参不能扩大范围。
- 审计查询只返回事件元数据（操作人、动作、对象标题/路径、结果）；正文读取仍走 KB/ACL 守卫，审计权限不扩大正文访问。

## 4. 设置委派

### 4.1 范围

设置分三层：

| 层 | 归属 | 说明 |
|---|---|---|
| 个人设置 | 所有成员 | 常规、用户信息、我的记忆；系统管理员设置弹窗只保留偏好、账户、版本 |
| 公司设置 | company_admin | 成员、部门、公司治理；技能目录只读，写入下放部门；不再包含技术配置 |
| 技术配置 | system_admin（`/ops` 运维工作台） | 模型、Ollama、解析器、存储、集成、工作区运行设置 |
| 知识库内设置 | manager / knowledge_admin | manager：基本信息、共享范围、发布、ACL；knowledge_admin：模型/解析/分块/多模态/存储/数据源（音频处理、知识图谱已停用） |
| 平台运维 | system_admin（`/ops` 运维工作台） | 系统信息、运行队列、平台 API Key、系统审计、账号救援 |

规则：

- 全局模型凭据、存储、解析器、向量库、MCP 不委派给部门角色，统一归 system_admin 运维台。
- KB 内模型选择只允许选择已存在、active 的模型，不允许新增供应商凭据。
- shared-in KB 设置只读。
- 设置入口由 caps 控制；页面内写操作仍由资源守卫兜底。

### 4.2 Settings 页面

- 公司 Settings 分区改为 caps 映射；技术配置迁到 `/ops` 运维工作台，不再出现在 Settings 弹窗。
- 移除沙箱配置、沙箱密钥、网络搜索。
- 保留技能；IM/API/CLI 集成迁到运维台。
- 技能分区：列表/编辑/授权；授权只对 skill 生效。
- 部门角色管理在“部门管理”页；不放进运维台技术配置。
- 无权限分区直接进统一 403，不再单独维护 role-denied 面板。

### 4.3 KB 内设置

- 入口在 KB 详情/设置抽屉，不在 Settings 模态。
- manager 可改基本信息、共享范围、发布、ACL；knowledge_admin 可改技术配置；editor/viewer 只读/不可见。
- 共享、发布与 ACL 全部归 manager；knowledge_admin 不参与。
- 所有设置变更写审计；高风险项（共享、ACL、模型切换）记录前后值。

## 5. 后端 API 约束

- 每个统计/审计 API 使用 `RequireCapability` 粗筛 + 服务层数据 scope。
- API 不接受前端任意 department scope；必须从调用者 membership 推导，或校验传入值等于允许范围。
- 聚合查询必须带 tenant + department/KB 范围；禁止先查全公司再前端裁剪。
- 统计/审计权限不改变 KB 正文访问；正文仍走 KB/ACL 守卫。
- 审计分页、导出按权限裁剪；导出写审计。

## 6. 阶段与交付

| 阶段 | 内容 |
|---|---|
| Phase 3.5 | caps/路由/403/设置分区能力化；Agent 面裁剪；不实现仪表盘 |
| Phase 5 | 部门运营台、公司治理台、审计查询页、设置委派 UI、E2E |

## 7. 验收

- manager 访问部门运营台成功，访问公司治理台 403；手改 `department_id` 拉别部门数据 403。
- knowledge_admin 可看部门统计，不能看审计。
- company_admin 可看全公司统计与全租户审计，只读；不进入 KB 正文，不能改共享/ACL/模型凭据。
- system_admin 才能进 `/ops` 运维工作台的系统设置与安全分区。
- 设置委派后，manager/knowledge_admin 可管理 KB 内设置；全局模型/存储/集成归 system_admin，company_admin 不再持有这些能力。
- 移除的沙箱/沙箱密钥/网络搜索入口不再出现；MCP/技能保留。
- 统计/审计响应不包含越权部门/KB 数据；正文读取/导出仍走 KB/ACL 守卫并写审计。
