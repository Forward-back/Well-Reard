# 术语与约定

> 状态：当前
> 最后更新：2026-10-26
> 目标读者：产品、开发、运维、AI Agent
> 关联：[系统总览](系统总览.md)、[角色生态位规定](../02-需求与设计/角色与权限/角色生态位规定.md)

本文只收跨文档容易产生歧义的术语。一个词只给一个 canonical 定义，并标注容易混淆的地方。实现细节、状态机和接口字段不放这里。

## 1. 组织与身份

| 术语 | 定义 | 不要混淆 |
|---|---|---|
| 公司 / 租户（tenant） | 当前本地部署的 WellRead 空间；本系统按单租户设计 | 不是 SaaS 多租户；不等于部门 |
| 空间 / 工作区（workspace） | 用户当前登录的 tenant 上下文 | 与“部门”不同；部门是公司内组织 |
| system_admin | 平台/技术总运维，管模型、解析、存储、集成、队列、账号救援 | 不是公司业务超级管理员；不进入 KB 正文 |
| company_admin | 公司治理角色，管成员、部门、公司看板/审计、技能目录只读 | 不兼任部门角色；不进入问答/KB/共享空间 |
| manager | 部门业务负责人：KB 生命周期、共享/发布/ACL、部门成员、CR 合并 | 不是公司治理；不能改全局技术配置 |
| knowledge_admin | 部门 KB 技术与内容维护：建库、模型/解析/分块/存储、文档/文件夹、技能 | 不删 KB、不共享/发布/ACL；不审 CR 合并 |
| editor | 部门内容编辑：上传/编辑文档、提交 CR/issue、评论 | 不建库、不删文档、不管文件夹/权限 |
| viewer | 部门知识消费者：阅读、检索、精读、共享空间、issue/评论 | 不生产内容、不提交 CR、不管理 |

## 2. 权限与访问

| 术语 | 定义 | 不要混淆 |
|---|---|---|
| 公司角色（company role） | `company_admin` 或 `member`，描述平台治理身份 | 不是部门角色 |
| 部门角色（department role） | `manager` / `knowledge_admin` / `editor` / `viewer`，描述部门内业务权限 | 同一空间只能有一个部门角色 |
| 能力码（capability） | `contracts/capabilities.json` 中的 key，如 `kb:read`、`kb:share_manage` | 不是独立授权真源；由角色派生 |
| 路由能力（route capability） | 路由 `requiredCaps` / `requiredAnyCaps`，用于菜单/路由/403 粗筛 | 不替代资源守卫 |
| 资源守卫 | 后端对部门、KB、共享、ACL、CR、API Key 的最终检查 | 前端隐藏不是安全边界 |
| 共享入（shared-in） | 其他部门共享给当前部门的 KB，只读入口 | 不是当前部门自有 KB |
| 共享出（shared-out） | 当前部门共享给其他部门的 KB | 只读方不能编辑/管理 |
| ACL allow | 在 KB 内对文件夹/文件显式允许 | 文件只支持 deny；文件夹可 allow/deny |
| ACL deny | 在 KB 内显式拒绝，优先于 allow 和角色 | 不是“角色降级” |
| 部门范围 | 调用者当前 `department_id` 决定的数据范围 | 前端传其他部门 ID 必须 403 |
| API Key capability | API Key 机器主体的能力（retrieve/chat/ingest/manage_kbs 等） | 不继承员工角色；独立 principal |

## 3. 知识与检索

| 术语 | 定义 | 不要混淆 |
|---|---|---|
| 知识库（KB） | 部门内文档与配置的集合 | 不是文件夹；不是共享空间 |
| 文档（Knowledge） | KB 内一条文档记录，含解析状态、元数据、chunks | 不是原始文件；原文件另存 |
| chunk | 文档切分后的检索单元 | parent/child 是两种粒度 |
| child chunk | 用于向量/BM25 召回的细粒度块（约 300 token） | 不是最终送 LLM 的上下文 |
| parent chunk | 用于生成上下文的粗粒度块（约 1200 token） | 不是召回单元 |
| 元数据 | 文号、机构、日期、类型、产品、生命周期、密级、部门等 | 不是文档正文 |
| 生命周期 | `draft` / `effective` / `expired` 等状态 | 不是解析状态 |
| 密级 | `internal` / `confidential` 等访问级别 | 不是部门归属 |
| RAG | 检索增强生成：召回、融合、重排、上下文、生成 | 不是单纯向量搜索 |
| 引用（reference） | 答案对应的文档/章节/原文片段及定位 | 不是普通 URL 列表 |
| trace | 一次问答的阶段耗时与候选链，用于调试/评测 | 不是用户原始问题日志 |

## 4. 协作与版本

| 术语 | 定义 | 不要混淆 |
|---|---|---|
| issue | 文档问题/讨论，可评论、关闭/重开 | 不是 CR |
| CR（变更请求） | 文档内容变更提案，经历草稿/提交/审批/合并/关闭 | 不是直接编辑 |
| reviewer | 单个 CR 被指定的审阅者，可审批/驳回该 CR | 不要求部门角色 |
| 部门审计员 | manager 维护的部门名单，可审批/驳回本部门所有 CR | 不是“看审计日志的人”；不能合并/关闭 |
| moderator | manager 在 KB 上的业务管理员权限，可审批/关闭/合并 | 当前唯一 merger |
| merge | 将 CR 变更写入正式文档 | 仅 manager；审阅者批准不等于合并 |
| version | 文档在某一时点的快照 | 不是 git commit |
| anchor comment | 绑定到文档选区/chunk 的评论 | 不是 issue 评论 |
| chunk lock | 协作编辑时对 chunk 的并发锁 | 不是 ACL |

## 5. 精读与技能

| 术语 | 定义 | 不要混淆 |
|---|---|---|
| ReadingRun | 一次交互式精读会话：固定文档集合、阅读计划、步骤、笔记、最终报告 | 不是普通问答会话 |
| Reading Notes | 增量阅读笔记：Confirmed/Terms/Open Questions/Contradictions/Decisions/Citations | 不是聊天记录 |
| reading model | 精读专用 `KnowledgeQA` 模型，租户级，由 system_admin 在运维台配置 | 不参与普通 RAG；运行时不切换 |
| grill-with-docs | 精读固定内置策略：先读后问、一次一个问题、带推荐解读、增量笔记 | 不是部门可编辑技能；不可替换 |
| ReAct | 精读内部受限推理循环：Thought→Action→Observation | 不是开放 Agent；只允许固定动作集 |
| skill | 可版本化的过程性知识包 `skill.md` | 不是工具权限；不是 Agent |
| per-skill grant | 对单个 skill 的用户/部门编辑授权 | 不改变角色矩阵；不适用于精读基础策略 |

## 6. 接入与部署

| 术语 | 定义 | 不要混淆 |
|---|---|---|
| MCP | Model Context Protocol 接入层，用 API Key 把知识能力暴露给外部 Agent | 不是员工账号 |
| CLI | `wellread` 命令行客户端 | 不是后端服务 |
| Lite | 单二进制 + SQLite 的轻量发行形态 | 不是当前全栈 compose 部署 |
| 生产态 | 实际公司内网部署，真实数据/密钥 | 不是演示数据 |
| 演示态 | 体验/演示用环境，样例数据、演示账号 | 不用于生产 |
| 本地数据目录 | `data/rag/`，存放 RAG 语料、模型、索引 | 不进入 git/镜像；不是公开目录 |

## 7. 命名与写作约定

- 角色叙事用中文名（系统管理员、公司管理员、部门负责人、知识库管理员、编辑、只读成员）；代码/caps 用英文 identifier。
- “公司/租户”固定写“公司”或“tenant”，不要混用“组织”；“空间/工作区”指当前 tenant 上下文。
- 当前文档名不带日期、Phase、批次；日期只写在文档头、交接快照、归档和截图索引。
- 文档状态只用：`当前`、`优化中`、`重构中`、`规划`、`历史`。
- 文档中路径按仓库根书写；跨目录链接优先相对路径。
- 每份文档一个主题；需求、功能、界面、进度、归档不混写。
- Mermaid 图必须有标题/上下文说明；图不替代正文。
- 不把完整角色矩阵复制到每份文档；统一引用角色文档。
- 不把 API 字段、数据库表结构复制到产品/功能文档；链接 Swagger/架构/子系统文档。
- 不在文档中写未经验证的性能数字、竞品结论或“最强/第一”。
